# 分层落地表（520pro · 哪些内联、哪些条件、哪些人工）

> 判据来自 368817 实测 + 本环境验证。核心修正：**项目级技能不路由，用户级技能可路由**——这是 520pro 把 TVBox 升到用户级的依据。

## 一、按"强制力通道"分档

| 档位 | 机制 | 可靠性 | 适合放什么 | 放哪 |
|---|---|---|---|---|
| **A · 薄壳内联** | `CODEBUDDY.md`（项目记忆，必注入） | ✅ 真阳性 | 必须"说到就做"的触发词、路由 | `<项目>/.codebuddy/CODEBUDDY.md` |
| **B · 常驻规则** | `alwaysApply:true` 的 `rules/*.md` | 🟡 用户级基本行 | 8 铁律、项目纪律 | `~/.codebuddy/rules/`、`<项目>/.codebuddy/rules/` |
| **B+ · 用户级技能** | `~/.codebuddy/skills/*/SKILL.md` | ✅ **可路由**（本环境验证） | 要跨项目复用的流程 | `~/.codebuddy/skills/` |
| **C · 条件规则** | `alwaysApply:false` + `paths` | ❌ 实测不注入 | 锦上添花补充契约 | `.../rules/*.paths.md` |
| **D · 项目级技能** | `<项目>/.codebuddy/skills/*/SKILL.md` | ❌ **不路由** | 仅作项目内说明 | `<项目>/.codebuddy/skills/` |
| **E · 人工第三通道** | 手机设置→指令（手动粘贴） | ✅ 手机唯一可靠 | 手机端铁律 | App「设置 → 指令」 |

## 二、本仓每个文件的落位理由

| 文件 | 档位 | 为什么 |
|---|---|---|
| `能力层/tvbox/skills/tvbox-pipeline` | **B+（用户级）** | 升到 `~/.codebuddy/skills` 才被注册、可路由、跨项目 |
| `能力层/tvbox/skills/probe-hub` | **B+（用户级）** | 同上；探源司只能用户级装 |
| `能力层/tvbox/skills/tvbox-core` | **不注册** | 无 `SKILL.md`，平台不认；只被上面两个技能 import |
| `能力层/tvbox/scripts/*.py` | 用户级路径 | 跟技能走，任何会话可调 |
| `能力层/tvbox/CODEBUDDY.md` | A | 项目隔离模式下的兜底；用户级模式下可不装 |
| `通用层/rules/core-8.md` | B（用户级） | 跨项目常驻；手机靠 E 兜底 |
| `能力层/tvbox/rules/tvbox-style.md` | B（项目级） | 项目隔离模式的纪律 |
| `能力层/tvbox/rules/tvbox.paths.md` | C | 条件示例，标注"可能不注入" |
| `手机指令.md` | E | 手机无项目工作区，只能人工 |

## 三、一条口诀

> **"说到就做"→ A 薄壳；"跨项目复用"→ B+ 用户级技能；"每次提醒"→ B 常驻；"锦上添花"→ C 条件；"手机必须靠谱"→ E 人工。**
> **别把技能放项目级**——那是不路由的 D 档，520pro 的整个修正就在这一点。
