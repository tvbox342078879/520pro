# 派活提示模板（子代理 / 新会话）

> **为什么有**：子代理是 **fresh context**——它看不到本会话的任何内容（不继承父上下文、记忆、刚才的讨论）。
> "按上面的方案改"对它等于"按空气改"。派活时**必须**把下面五段显式写进提示词。
> 依据：core-8 `B-07`（换模型对账）+ `B-03`（先验开工）。

## 固定基线（每次必填，缺一不可）

| # | 段 | 写什么 | 缺了会怎样 |
|---|---|---|---|
| 1 | **位置与版本** | 仓库绝对路径 + `git log --oneline -1` 的 sha + `VERSION` 内容 | 它会在错误目录/旧版本上动手 |
| 2 | **当前主线** | 一句话：这次要达成什么、**明确不做什么** | 它会顺手"优化"别的文件，改动范围失控 |
| 3 | **关键术语** | 3–5 个本仓特有概念（如"基座/薄壳/正门/真源"），各一句解释 | 它按通用语义理解，产出词不达意 |
| 4 | **禁改区** | 不许动的文件/目录、不许 amend 的提交、不许碰的仓库 | 别人的改动被覆盖（它不知道有人在并行） |
| 5 | **交付与验收** | 只回结论 / 改哪些文件 / 出什么报告；验收命令原文 | 它给你一大段散文，你还要返工 |

## 提示词骨架

```text
【位置】仓库 /abs/path/520pro，HEAD=<sha>，VERSION=<x.y.z>。
【主线】<一句话目标>；本次**不做** <明确排除项>。
【术语】<术语1>=<一句解释>；<术语2>=<一句解释>；<术语3>=<一句解释>。
【禁改】不要动 <路径列表>；不要 rebase/amend 已有提交；不要改 <运行时数据>。
【任务】<具体到文件与函数/小节；给出判据与反例>。
【交付】只回：改了什么文件 + 每处为何 + 验证命令与结果；不要贴全文。
【验收】<命令原文，如 python3 verify/terminology_check.py --repo .> 必须全绿；
        失败就说失败，不许"应该没问题"。
```

## 反例（都会导致返工）

- ❌ "按上面的方案去改" —— 它看不到上面的方案。
- ❌ "把文档整理一下" —— 没有范围、没有判据，必然过度编辑。
- ❌ "你看着办" —— 它会把"看着办"实现成"重写一遍"。
- ❌ 只给相对路径 —— 子代理的 cwd 不一定是你以为的那个。

## 收活检查（派活方自检）

1. 它回报的 commit / 文件路径，与我给的位置一致吗？
2. 它说"通过"时，有没有贴命令与输出？没贴就按**无法判定**处理（B-02）。
3. 它有没有动禁改区？`git status` 一看便知。
