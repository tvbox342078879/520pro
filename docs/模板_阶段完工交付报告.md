> **用途**：每完成一个施工阶段（工程 A–F、第 N 段、重大修复）按本模板出一份报告。
> **真源**：规则以 `通用层/rules/core-8.md` 为准，版本与变更以 `MANIFEST.json` 为准，判据以 `verify.sh` + `verify/*.py|json` 为准。报告只**引用**、不重定义（M2）。
> **本文件是模板正本**（仓内 `docs/`）；别处出现副本只许留指针，不许平行维护（M1）。
> **交付形态**：用户点名要文件才落库（`space-hub archive`）；没点名就在回复里给结论（B-09）。

## 九、回滚路径（破坏性/批量动作必填）

> 判据：**"如果现在发现改错了，别人能不能照着这一节恢复"**。写不出可执行命令 = 没写。

| 动作 | 回滚方式（可直接执行） | 窗口 / 代价 |
|---|---|---|
| 代码/文档改动 | `git revert <sha>` 或 `git checkout <sha> -- <路径>` | 秒级；已推送需再推一次 |
| 批量移动/改名 | 按 `snapshots/<时间戳>_state.json` 的 `origin_parent` 逐项 `restore` | 分钟级；依赖快照未被 GC |
| 云端节点删除 | **不可回滚**：写清事前快照/清单位置与备份 | 永久 |
| 安装副本被改坏 | `bash install.sh`（按原 SCOPE 重装）+ `bash verify.sh` | 分钟级 |

**写不出回滚路径时**：先补快照/清单再动手，不许"先干了再说"。
