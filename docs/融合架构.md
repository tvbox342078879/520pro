# 融合架构：我的生态 × 新生态

> 目标：不是二选一，而是**把我的"平台硬机制"接到你的"可移植业务"上**。本文件讲清"接在哪、为什么、靠不靠得住"。

## 一、两张底牌的差异

| | 我当前的生态（平台运行时） | 新生态（你自建的软规则包） |
|---|---|---|
| 规则注入 | 系统提示，**每轮强注入** | `CODEBUDDY.md`/`rules` 文件，可能不加载 |
| 技能 | 平台注册，**按 description 能路由** | 项目级 `.codebuddy/skills`，**不注册、不路由** |
| 强制力 | 准硬约束（合规/鉴权/交付） | 软约束（读到了才遵守） |
| 执行 | 云端沙箱（Ubuntu） | 你的本机/项目 |
| 跨设备 | 账号打通 | 需手动搬 |

**结论**：我这边"硬"是因为这些机制属平台；你那边"软"是因为要在平台之外模拟它们。

## 二、融合的落点（把软的接到硬的上）

| 新生态组件 | 接到我的哪个硬机制 | 做法 |
|---|---|---|
| 8 条铁律 | 平台账号指令（硬轨）+ `core-8.md`（软轨） | **双轨**，两边都放 |
| TVBox 技能 | 平台技能注册（用户级） | 装到 `~/.codebuddy/skills/` → 可路由 |
| TVBox 脚本 | 云端沙箱执行 | 装到 `~/.codebuddy/scripts/`，任何会话可调 |
| tvbox-agent | 子代理隔离 | 装 `~/.codebuddy/agents/`，重活派出 |
| 薄壳 CODEBUDDY | 项目记忆（必注入） | 保留，做项目业务兜底 |
| 真源 | GitHub / 资料库 | 沙箱只当窗口 |

## 三、关键修复：技能"放错层"

- 现象：项目级 `.codebuddy/skills/` 技能**不进 active 列表、不路由**（368817 `L2.skill`）。
- 证据：本环境 `~/.codebuddy/skills/` 下的 `automation-task-manager`、`library`、`github-connector` 等**都在 active 列表、可触发**。
- 修复：TVBox 技能从项目级 → **用户级**。`install.sh --user-skill` 负责这件事。

## 四、可靠性（三态）

| 机制 | 结论 | 证据 |
|---|---|---|
| 用户级技能路由 | ✅ 真阳性 | 用户级技能在 active 列表 |
| 薄壳注入 | ✅ 真阳性 | "仅 CODEBUDDY.md 被注入" |
| 用户级 core-8 | 🟡 一次真阳性 | 手机历史真阴性 → 双轨兜底 |
| 条件规则 paths | ❌ 真阴性 | 实测不注入 |
| 项目级技能路由 | ❌ 真阴性 | 未进 active 列表 |
| 用户级技能跨设备到新手机 | ❓ **无法判定** | 需实测：新机说"更新TVBox配置"看是否触发 |

## 五、手机端

- 规则：手机 App **2.8.0/2.9.1 两版均无**「给 WorkBuddy 的指令」入口（2026-11-13 实测，更新后复查仍无）→ 手机端硬轨改走**会话首条粘贴**；桌面版入口在 设置→个性化→给 WorkBuddy 的指令。
- TVBox：若用户级技能随账号同步到手机（**待实测**），则**手机也能触发**——因为执行在云端沙箱，不在手机。
- 若不同步：手机只做规则文本 + "去电脑端跑"提示。

## 六、一句话

> **硬的用平台的（账号指令/用户级技能/子代理/云端沙箱），软的自建（核心规则/薄壳/业务脚本），真源上云。**
> 这不是"把两套拼起来"，而是"让自建业务跑在平台硬机制上"。
