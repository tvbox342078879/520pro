# 通病台账（重复犯的错）

> **与 `docs/遗留登记.md` 的分工**：这里是**病历**——同一种错反复出现，记形态、记复发次数、记机制落点；
> 那里是**待办**——一次性的活，做完就删行。两者不合并：待办会清零，通病不会清零，只会被机制压住。
>
> **登记口径（B-14 三齐）**：每条必须有 owner / next / due；缺一即无效。
> **状态**：`active`（已确认，须防）／`candidate`（疑似，等下一次实例转正）／`retired`（已被判据守住，降为观察）。
> **复发记录格式**：`YYYY-MM-DD · 实例坐标（文件:行 或 现场证据）· 一句话`.
>
> 来源：旧生态 `tvbox-eco` 的 `rules/disposition_ledger.json`（9 条），本次只迁与 520 相关的 4 条，
> 其余 5 条因"旧检查器/旧设施专属"不迁（判定见 `docs/规则迁移映射_193条.md` D 类）。

## 病8 · 单信号查不到即判"不存在"

| 字段 | 内容 |
|---|---|

| 形态 | 用一个不封闭的通道（单页查询、单次 grep、单源）查不到，就直接下"没有/没动/不存在"的结论——假阴性方向。 |
| 实例（旧） | 旧生态记录：审查侧用单通道缺失信号判断"某规则未落地"。 |

## 病10 · 中文文件名被 git 转义（路径比对永远不相等）

| 字段 | 内容 |
|---|---|
| 状态 | **candidate**（2 次实例，判据未落地） |
| 形态 | `git diff --cached --name-only` / `ls-files` 默认把非 ASCII 路径转义成 `"docs/\346\226\260..."`，与代码里的中文字面量比对**永远 False**。后果两个方向：闸静默放行（假绿），或测试前置断言假红（让人去修一段没坏的代码）。 |
| 实例 | ①2026-11-13 · `hooks/pre-commit` ② 段首版：`grep -qx '手机指令.md'` 永远匹配不上 → 云端同步形同虚设（该段注释已记）；②2026-11-14 · `verify/tests/test_commit_fields.py` 例4 的 `stage()` 漏加 `-c core.quotepath=false`，前置断言报「新文件没进暂存」，实际进了——差点误判成「Reuse 对账失效」。 |
| 边界 | 管：git 输出的路径与中文/非 ASCII 字面量做相等比较。不管：编码问题导致文件读写失败。 |
| 机制落点 | **暂无判据**。目前只有两处注释提醒（`hooks/pre-commit` ② 段、`hooks/commit-msg` 的 `STAGED_ADD` 行）。注释不是判据，压不住第三次。 |
| owner / next / due | 我 / 第三次实例出现即写扫描器（扫 `verify/`、`hooks/` 下所有 `git diff --cached`/`ls-files` 调用，缺 `core.quotepath=false` 即红）/ 下次同类坑出现时 |

## 病11 · 引用已作废结论，不查真源是否已有订正

| 字段 | 内容 |
|---|---|
| 状态 | **candidate**（1 次实例，判据已落地：`verify.sh` 作废结论残留闸） |
| 形态 | 真源已有修正记录，但散落副本（规则文件、技能文档）没人同步；后续会话引用的是旧副本，把已作废结论当作现役事实说出来。实质是 M5「变更连带」断链 + B-06「凭记忆断言环境事实」的合谋。 |
| 实例 | ①2026-11-14 · 「手机不跑钩子」——真源 `docs/钩子来源判定.md` 于 2026-11-12 已写明作废，但 `core-8.md:48`、`zh-style.md:24`、`工程纪律.md:56`、feature-gate、machine-bootstrap 五处副本仍带旧口径，AI 连续多轮引用并向用户复述，被用户以手机端钩子实测截图当场抓住。 |
| 边界 | 管：真源已订正、副本未同步、被再次引用。不管：真源本身就错（那是真源质量问题，先修真源）。 |
| 机制落点 | `verify.sh` 新增「作废结论残留」段：全仓 grep 旧口径文案，仅允许命中真源（`docs/钩子来源判定.md`）、台账本行与判据自身；其余命中即红。同类作废结论进真源时须在此段登记其关键词。 |
| owner / next / due | 我 / 下一类「真源已订正」的事实入库时，同步在 verify.sh 残留闸登记关键词 / 每次出现即触发 |

## 维护

- 新增一条病：先问"这是孤例还是模式"（B-15）——单次错误进 `docs/遗留登记.md`，反复出现的才进本表。
- 判据已经把某条病压住的，状态改 `retired` 并写明"哪个判据在守"，不要删行（删了就看不出它曾经反复）。
- 每次巡检（inspect-hub 死门读 `docs/遗留登记.md`）之外，本表按季度人工过一遍：谁还在 active、复发次数有没有涨。
