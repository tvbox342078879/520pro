# 通病台账（重复犯的错）

> **与 `docs/遗留登记.md` 的分工**：这里是**病历**——同一种错反复出现，记形态、记复发次数、记机制落点；
> 那里是**待办**——一次性的活，做完就删行。两者不合并：待办会清零，通病不会清零，只会被机制压住。
>
> **登记口径（B-14 三齐）**：每条必须有 owner / next / due；缺一即无效。
> **状态**：`active`（已确认，须防）／`candidate`（疑似，等下一次实例转正）／`retired`（已被判据守住，降为观察）。
> **复发记录格式**：`YYYY-MM-DD · 实例坐标（文件:行 或 现场证据）· 一句话`.
>
> 来源：旧生态 `tvbox-eco` 的 `rules/disposition_ledger.json`（9 条），本次只迁与 520 相关的 4 条，
> 其余 5 条因"旧检查器/旧设施专属"不迁（判定见 `docs/规则迁移映射_193条.md` D 类）。

## 病10 · 中文文件名被 git 转义（路径比对永远不相等）

| 字段 | 内容 |
|---|---|
| 状态 | **candidate**（2 次实例，判据已落地 2026-11-14：`verify/gate_scan.py --gate quotepath`） |

| 边界 | 管：git 输出的路径与中文/非 ASCII 字面量做相等比较。不管：编码问题导致文件读写失败。 |

## 病14 · 重建/新建时凭常识造枚举值，未扫真实取值

| 字段 | 内容 |
|---|---|
| 状态 | **candidate**（1 次实例；判据待落地，见机制落点） |
| 形态 | 建 `select` 字段时按「这东西应该是哪几档」凭常识列举选项，而不是去真实数据里 `distinct` 一遍。后果不是建库失败，是**建库成功、写入全崩**——平台不回退不自动造选项，整条记录被拒或该列被静默清空。 |
| 实例 | 2026-11-14 重建探源 6 库：`监测周期` 建成「日/周/月/季」、`活跃度` 建成「高/中/低/停更」，看着完全合理；回灌 186 条本地数据时报 `字段「监测周期」没有选项 ['每周']`，新增成功 0/186。真实取值是「每周/每月」与「活跃/停滞/归档/待查」——**四档全错，无一命中**。 |
| 边界 | 管：任何新建 `select`/`multi_select` 字段的场合（建库、加字段、改选项）。不管：`text` 字段（无枚举约束）、以及确有权威枚举表可查的场合（如 `PLATFORM_FORMS` 八档有实测注释，照抄即可——那不算凭常识）。 |
| 机制落点 | **暂无判据**。可落地形态：①有存量数据时，建字段前先 `distinct` 真实取值并打印对照（人工必做）；②无存量数据时，按代码里的**写入键**取值（`{'select': X}` 的所有 X 字面量）静态汇总，且交付时明确标注「选项未经真实数据校验」。`verify/gate_scan.py` 可加一道 gate：新建库的 schema 生成脚本里出现 `select` 而注释无取值来源，即警示。 |
| owner / next / due | 我 / 下次建库或加 select 字段前执行①或②，并决定是否把 gate 写进 `gate_scan.py` / 2026-11-16 |
