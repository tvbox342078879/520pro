## 1. 为什么必须"四件套"一起装

探源司**不是独立工具**，它是生态成员。只装 `probe-hub` 必然崩：

```
$ python3 probe.py monitor status
ModuleNotFoundError: No module named 'core'
```

| 技能 | 提供 | 缺了会怎样 |
|---|---|---|
| `probe-hub` | 探源司本体（`probe.py`，约 559KB） | 没有能力 |
| **`tvbox-source-hub`** | **`core.py` 41KB + `concurrency.py` 14KB** | **直接崩（上面那个报错）** |
| `tvbox-interface` | 测活口径 `pipeline.py` 52KB | 判据缺失，结果不可信 |
| `tvbox-source-blacklist` | `blk.py` | 无法剔除垃圾源 |

> `install.sh --user-skill` 已改为**循环安装全部技能**，这四个会自动到位。

## 4. 立刻可用（不用等新会话）

## 6. 三条边界（如实）

| 边界 | 说明 |
|---|---|
| **只能用户级装** | `probe.py` 靠 `~/.codebuddy/skills/tvbox-source-hub/scripts` 定位 `core`；`--capability-only`（项目级）下探源司**起不来** |
| **路径已做可迁移** | 原仓库 25 个文件里 73 处硬编码 `/root/.codebuddy`，已用 `fix_paths.py`（tokenize 精确替换）改为 `os.path.expanduser('~/.codebuddy/...')`。在 `/tmp/demo` 这种非 root HOME 实测通过 |
| **沙箱 ≠ 真机** | 装在临时容器里的 `~/.codebuddy` 一重置就没。真机要在**自己的电脑**跑本文第 2 节 |

## 8. 常用排查

| 现象 | 原因 | 解法 |
|---|---|---|
| `ModuleNotFoundError: No module named 'core'` | 只装了 `probe-hub`，缺 `tvbox-source-hub` | 重跑 `bash install.sh --user-skill` |
| `monitor status` 无输出/超时 | 沙箱或云电脑 443 出站受限 | 记**无法判定**，换网络环境重试；不是能力缺陷 |
| `云端监测册不可达` | 未授权/网络异常 | 已自动降级本地册，**可用** |
| `内容指纹未取到` | 仓库主页不可达，仅 API 通 | 存活可判，变更判**无法判定** |
| 新会话说"查一下源"没反应 | 技能未加载（旧会话）或未装用户级 | 新开会话 / 重跑 `--user-skill` |

## 9. 探源司真实性的 4 条硬指标

判断它是"真查了"还是"编的"：

| # | 指标 | 不达标 = 没干活 |
|---|---|---|
| 1 | 有落盘产物 | `monitor_targets.json` / `dead_repos.json` 的 mtime 更新 |
| 2 | 有 `http_code` | 每条结论附返回码；**没返回码的"我查到了"一律判无法判定** |
| 3 | 三态齐备 | "无法判定"不许被压成"失败" |
| 4 | 反证不倒 | 给个假仓库 → 必须明说"未找到"，不编造提交记录 |
