# 多场景部署指南

> 按「你要达到什么目的」选场景，不要一律从头 clone。**换机才需要下载仓库；日常验证、看源码、别人试用各有更轻的路子。**
> 真源：换机流程见 `通用层/skills/machine-bootstrap/SKILL.md`，命令契约见 `bootstrap.sh:5`，稀疏清单见 `MANIFEST.json` 的 `sync_shape`。

## 场景速查

| 你的情况 | 走哪条 | 要不要下载仓库 | 关键风险 |
|---|---|---|---|
| 普通网络换新设备 | 场景 A（bootstrap 完整） | 是，2.4～2.8M 稀疏 | 无 |
| 弱网卡在 git clone | 场景 B（raw 单文件补包） | 是，逐文件 1.2M | 补包后无完整 `.git` |
| 已有仓库，只想验证能不能用 | 场景 C（不换机） | 否 | 装完须开新会话才生效 |
| 一台机两账号多会话测换机 | 场景 D（并发边界） | 视情况 | 写操作须串行 |
| 别人拿你的仓去用 | 场景 E（匿名部署） | 是（他自己下） | 他写不了你的仓库 |

## 场景 A · 普通网络换机（完整 git 工作副本）

一条命令：克隆 + 稀疏检出 + 断言 +（可选）装用户级。

```bash
# 完整版（默认 full，约 2.8M）
bash bootstrap.sh https://github.com/tvbox342078879/520pro.git full ~/520pro --install

# 探源司最小集（lite，约 2.4M，只含 probe-hub + tvbox-core + 脚本）
bash bootstrap.sh https://github.com/tvbox342078879/520pro.git lite ~/520pro --install

# 先预览不落盘
bash bootstrap.sh https://github.com/tvbox342078879/520pro.git lite /tmp/x --dry-run
```

- 三条承诺：**幂等**（重跑跳过 clone，仅 `git pull --ff-only` + 重设稀疏）、**零明文 token**（默认匿名；只有匿名失败才用环境变量里的 token，用完立即清，不写 `.git/config`）、**失败显式**（报错即非 0，不静默降级）。
- 装完**开新会话**才加载规则/技能；同会话里验不到。
- 再跑 `check-env.sh` 做换机后验收（A/B/C 任一命中即 rc=2）：
  ```bash
  bash ~/520pro/通用层/skills/machine-bootstrap/scripts/check-env.sh --repo ~/520pro --install ~/.codebuddy
  ```

## 场景 B · 弱网 git clone 失败（raw 单文件补包）

**判定条件**：preflight 网络 OK、`curl` 单文件可达，但 `git clone` 三次都报 `GnuTLS recv error (-110)` 或 `could not fetch ... from promisor remote`。根因是 git smart protocol 的 TLS/blob 通道被掐断，curl（OpenSSL 后端）的普通 HTTPS 仍通。

```bash
# 1) 下补包器 + 逐文件清单（各一个小文件，curl 可达）
curl -fsSL https://raw.githubusercontent.com/tvbox342078879/520pro/main/通用层/skills/machine-bootstrap/scripts/raw_sync.py -o /tmp/raw_sync.py
curl -fsSL https://raw.githubusercontent.com/tvbox342078879/520pro/main/通用层/skills/machine-bootstrap/references/sync_filelist.txt -o /tmp/sync_filelist.txt

# 2) 逐文件补包（断点续补：已存在非空的自动跳过）
python3 /tmp/raw_sync.py --repo tvbox342078879/520pro --list /tmp/sync_filelist.txt --dest ~/520pro --retries 5
```

- **清单只含文本真源**（742 个文件、约 1.2M），**排除 `capability_63/runtime_assets` 的 8 个逆向运行时大文件**（frida/python/node 等约 200M）——换机断言不查它们，弱网不必搬。
- 退出码 = 失败文件数：`0` 全成功；非 0 把失败文件名报回，可重跑（跳过已成功的）。
- **边界（重要）**：补出来的是**纯文件集，无完整 `.git`**。能直接用规则/技能/命令，但**不要再跑** bootstrap 的 `apply_sparse` 或依赖 `git ls-files` 的 verify（会假失败）。等有网后重跑场景 A 换成完整 git 仓库。
- 中文路径自动 UTF-8 编码；关键件（MANIFEST/VERSION/install/bootstrap/verify）优先下载，失败早暴露。

## 场景 C · 已有仓库，只验证能不能用（不换机）

仓库已在 `~/520pro`，不要重新 clone。装一次用户级，开新会话发探针验证三通道：

```bash
bash ~/520pro/install.sh --user-skill          # 装规则/技能/agents/commands 到 ~/.codebuddy
```

然后**开新会话**，分别验证：
- 薄壳：`~/.codebuddy/CODEBUDDY.md` 在位
- 规则目录：`~/.codebuddy/rules/` 有 `core-8.md` + `施工纪律.md`
- 技能路由：随口问一句触发词（如"换机""体检"），看是否命中对应技能

三态诚实：命中=真阳性；明确不命中=真阴性；没查到≠没有，记「无法判定」。

## 场景 D · 一台机两账号多会话测换机（并发边界）

账号隔离的是**云端身份**，不是本机文件。两个账号跑在同一台机，`~/.codebuddy/`、`~/520pro`、各账本 json 都是**同一份物理文件**，照样会撞。

| 操作 | 能否多会话并行 |
|---|---|
| 只读 / verify / 发探针验证 | ✅ 随便开 |
| 改规则 / 装技能 / 写账本 json | ❌ 一次只让一个会话做，否则后写覆盖先写（无告警） |
| 同时 commit/push 同一仓库 | ⚠️ 后者 non-fast-forward 被拒；提交留本地，`git pull --ff-only` 后重推即可 |
| 跑 bootstrap / install | ❌ 单一会话跑完，其他会话等装完再开新会话验证 |

**推荐分法**：账号 A 管配置与写入，账号 B 只做验证/只读换机一次，别多会话同时换。

## 场景 E · 别人拿你的仓库去用

**别人部署不会写你的仓库**。你的仓是公开仓，匿名只能 clone + 读；写权限由 GitHub 后台的协作者名单控制，只有你亲自加的人才推得上去。

- 别人走场景 A（普通网络）或场景 B（弱网）即可，各自下到自己机器。
- **唯一危险**：把凭证（token、`.gh_token`、网盘 cookie）发给别人——那对方能冒充你写仓库。命令和仓库地址可以给，**凭证绝不能给**。
- 你的仓库具体加了哪些协作者，需到 GitHub 后台查看（本地查不到）。

## 附：三种"下载"别混淆

- **换机下载**（场景 A/B）：拿仓库源码，几 MB，一次性。
- **日常用**（场景 C）：不下载，仓库已在本地。
- **资料库/产物**：走 space-hub 归档，登录云端即得，**不进工作副本**（`machine-bootstrap/SKILL.md` 诚实边界）。
