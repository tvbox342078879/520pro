# 加载机制与可靠性（520pro · 实测留档）

> 结论档案，供换机/换人直接引用。**核心订正：技能路由看"层级"——用户级路由，项目级不路由。**

## 一、加载机制（CodeBuddy 侧）

| 机制 | 路径 / 字段 | 是否原生加载 | 实测 |
|---|---|---|---|
| 项目记忆（薄壳） | `./CODEBUDDY.md` 或 `./.codebuddy/CODEBUDDY.md` | 是，**必注入** | ✅ "仅 CODEBUDDY.md 被注入" |
| 用户级规则 | `~/.codebuddy/rules/*.md` | 是（alwaysApply 常驻） | 🟡 单会话真阳性 |
| 项目级规则 | `<项目>/.codebuddy/rules/*.md` | 是（alwaysApply 常驻） | 🟡 理论行，CWD 需在项目根 |
| 条件规则 | `alwaysApply:false` + `paths` | 官方有字段，宿主未兑现 | ❌ 不注入 |
| **用户级技能** | `~/.codebuddy/skills/*/SKILL.md` | **是，按 description 路由** | ✅ **命真阳性（本环境技能均在 active 列表）** |
| **项目级技能** | `<项目>/.codebuddy/skills/*/SKILL.md` | 不注册 | ❌ 不进 active 列表、不路由 |
| 钩子 | `hooks/` | 支持 | **已装**（v0.8.37 起 `pre-commit` + `commit-msg` 双钩子；手机端会话实测生效，2026-11-14 `commit-msg` 在手机端会话拦截过一次错误提交）。旧结论「手机不跑钩子」已作废，见 `docs/钩子来源判定.md` |

## 二、强制力梯度（官方）

```
软声明  →  config  →  permissions.deny  →  hook
（最弱）                                      （最强）
```

本生态只用第一级（软声明）+ 尽量借平台硬机制（账号指令、用户级技能、子代理、云端沙箱）。

## 三、为什么"用户级技能"是 520pro 的关键

- 项目级技能不注册、不路由（368817 `L2.skill`）→ 所以"技能自动调用"在项目级永远打折。
- 用户级技能被平台注册（本环境 `automation-task-manager`、`library`、`github-connector` 等均在此层且可触发）→ **放到用户级，路由问题直接解决**。
- 且执行在**云端沙箱**，不在手机 → 手机登录同账号后，**有希望直接触发**（跨设备同步=待实测）。

## 四、结论一句话

> **规则双轨（账号指令硬轨 + core-8 软轨）；能力放用户级技能（可路由）+ 云端沙箱（可跨设备执行）；薄壳做项目兜底；条件规则只当示例。**
> 这仍是"软约束为底"，但比纯自建多了三样平台硬机制。
