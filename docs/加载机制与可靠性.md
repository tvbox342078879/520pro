# 加载机制与可靠性（520pro · 实测留档）

> 结论档案，供换机/换人直接引用。**核心订正（2026-11-21 二次实测推翻旧结论）：平台按"是否在项目根"路由技能，不是按"用户级/项目级"——放在平台项目根 `.codebuddy/skills/` 下的技能照常路由。**

## 一、加载机制（CodeBuddy 侧）

| 机制 | 路径 / 字段 | 是否原生加载 | 实测 |
|---|---|---|---|
| 项目记忆（薄壳） | `./CODEBUDDY.md` 或 `./.codebuddy/CODEBUDDY.md` | 是，**必注入** | ✅ "仅 CODEBUDDY.md 被注入" |
| 用户级规则 | `~/.codebuddy/rules/*.md` | 是（alwaysApply 常驻） | 🟡 单会话真阳性 |
| 项目级规则 | `<项目>/.codebuddy/rules/*.md` | 是（alwaysApply 常驻） | 🟡 理论行，CWD 需在项目根 |
| 条件规则 | `alwaysApply:false` + `paths` | 官方有字段，宿主未兑现 | ❌ 不注入 |
| **用户级技能** | `~/.codebuddy/skills/*/SKILL.md` | **是，按 description 路由** | ✅ **命真阳性（本环境技能均在 active 列表）** |
| **项目级技能（放对根）** | `<平台项目根>/.codebuddy/skills/*/SKILL.md` | 注册 | ✅ **本机实测真阳性**（2026-11-21 二次实测）：平台项目根＝`IDE_WORK_DIR`（即 IDE 工作目录，非仓库子目录）；探针放 平台项目根 `.codebuddy/skills/` → 新会话 available_skills 出现该 folder、探针在列（测后即删）。首次把探针放仓库子目录 `.codebuddy/skills/` 未路由，只因那不是平台项目根，**不是平台不支持项目级** |
| 钩子 | `hooks/` | 支持 | **已装**（v0.8.37 起 `pre-commit` + `commit-msg` 双钩子；手机端会话实测生效，2026-11-14 `commit-msg` 在手机端会话拦截过一次错误提交）。旧结论「手机不跑钩子」已作废，见 `docs/钩子来源判定.md` |

## 二、强制力梯度（官方）

```
软声明  →  config  →  permissions.deny  →  hook
（最弱）                                      （最强）
```

本生态只用第一级（软声明）+ 尽量借平台硬机制（账号指令、用户级技能、子代理、云端沙箱）。

## 三、为什么"用户级技能"是 520pro 的关键

- 项目级技能路由（2026-11-21 二次实测订正）：**旧结论"项目级不路由"错误**。首次实测把探针放 仓库子目录 `.codebuddy/skills/` 未进路由列表，误判为"平台不支持项目级"；用户指出"会不会是我们机制问题"后复查——平台项目根是 `IDE_WORK_DIR`（指向 IDE 工作目录），把探针放 平台项目根 `.codebuddy/skills/` 后，新会话 available_skills 新增该 folder、探针在列。→ 结论：**技能放对平台项目根即可路由**；TVBox 升用户级仍成立（跨项目/跨设备），但"项目级不路由"不再是理由。
- 用户级技能被平台注册（本环境 `automation-task-manager`、`library`、`github-connector` 等均在此层且可触发）→ **放到用户级，路由问题直接解决**。
- 且执行在**云端沙箱**，不在手机 → 手机登录同账号后，**有希望直接触发**（跨设备同步=待实测）。
- **跨会话/换设备分环境（2026-11-21 订正，用户指出"520 已不完全依赖官方"）**：520 能力不依赖官方账号技能库——MANIFEST `skill_discovery_mechanism` 真阳性（Skill 工具扫 `~/.codebuddy/skills/`，文件在即加载）、`sandbox_persistence_desktop` 真阳性（桌面沙箱/云电脑 `~/.codebuddy` 跨会话持久）。**当前环境＝CloudStudio 云电脑持久沙箱**（`X_IDE_IS_CLOUDSTUDIO=TRUE`），技能装一次跨会话长期可用；本项目探针在新会话（子代理）路由列表出现即实证。只有**手机普通聊天沙箱**每次新建、本地副本即丢（`sandbox_persistence_phone` 真阴性，2026-11-21 精确化）——但"本地副本消失"≠"能力不可用"：记忆与能力真源在 git 远端（`docs/` 21 篇 md + 经验库 + 判据 + `通用层/skills/`），`bootstrap.sh` 幂等 clone/pull 可从 git 重拉全套（恢复清单 FALLBACK_LITE/FULL 含 docs/skills/verify），开场自检自动重装。→ 手机端"每次重装"是**从 git 恢复**而非从零攒内容；记忆不丢靠 git 真源，不靠沙箱本地持久。仍需在手机端实测 `bootstrap.sh` 冷启动链端到端（无法判定）。→ 旧表述"跨设备同步=待实测/项目级换设备不可用"过于笼统，正确口径是**分环境**：持久云电脑跨会话跨设备（同一持久环境）可用，手机临时沙箱不可用。

## 四、结论一句话

> **规则双轨（账号指令硬轨 + core-8 软轨）；能力放用户级技能（可路由）+ 云端沙箱（可跨设备执行）；薄壳做项目兜底；条件规则只当示例。**
> 这仍是"软约束为底"，但比纯自建多了三样平台硬机制。
