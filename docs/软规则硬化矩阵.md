# 软规则硬化矩阵（core-8 十八条 × 钩子可观测性）

> 目的：回答「哪些软条款能用钩子变硬、哪些永远硬不起来」。
> 判据不是「重要不重要」，而是**钩子能不能观测到它在发生**。
> 版本：2026-11-14 首版。改条款或改钩子能力后必须回来更新本表。

## 一、钩子只有四个观测面

平台支持 9 个事件（`PreToolUse` / `PostToolUse` / `UserPromptSubmit` / `Stop` /
`SubagentStop` / `SessionStart` / `SessionEnd` / `PreCompact` / `Notification`），
但对「行为是否正确」真正有用的观测面只有四个：

| 观测面 | 事件 | 能看到什么 | 看不到什么 |
|---|---|---|---|
| ① 命令串 | PreToolUse·Bash | `tool_input.command` 原文 | 命令跑起来之后会发生什么 |
| ② 文件路径 | PreToolUse·Write/Edit | `tool_input.file_path` | 写进去的内容对不对 |
| ③ 工具结果 | PostToolUse | `tool_response` | 模型怎么理解这个结果 |
| ④ 回合文本 | Stop | transcript 路径 + 本轮全部消息 | 模型的内部推理过程 |

**一个条款能被硬化，前提是它的违反行为会在这四个面之一留下可正则化的痕迹。**
做不到这一点的条款，加钩子只会造出「看着拦、其实没拦」的假闸——比不设防更糟。

## 二、六级强度（本表用这套刻度）

| 级别 | 含义 | 违反后果 |
|---|---|---|
| **S1 硬阻断** | PreToolUse deny，动作根本发不出去 | 做不成 |
| **S2 拽回** | Stop 钩子 exit 2，模型被拉回来继续（`stopHookFeedback` 注入） | 说不完，得重说 |
| **S3 事后提醒** | PostToolUse `type: prompt`，动作已发生，事后提示模型自查 | 可能已被忽略 |
| **S4 开机注入** | SessionStart 注入上下文 | 模型可能不读 |
| **S5 变更闸** | pre-commit / verify.sh，改动能拦、运行时行为拦不住 | 事后拦 |
| **S6 纯文本** | 只写在规则文件里 | 全凭模型自觉 |

| B-15 | 孤例还是模式 | ①③⑤（部分） | **S5（v0.8.66 部分硬化）** | S5 | 模式识别的机器面已接线：拦截递病历（guard_cmd）+ Lesson 复发机器记账（commit-msg→guard_cmd --bump，v0.8.66）+ 痊愈机判（chk_cure 10 日无复发自动降级，v0.8.66）+ 内容流四判据接电 verify.sh（gate_experience，v0.8.66——闸此前只在巡检 run 跑，未接电=形同虚设）。「孤例还是模式」的语义判定与四步闭环仍是人工面 |
| B-16 | 双核必保 | ① 命令串 | **S1（已落地 G4）** | S1 | `rm/mv/git rm` 目标含 `tvbox-core` / `probe-hub` 直接拦 |
| B-17 | 代号即确认 | 无 | S6 | 硬化不了 | 需要理解用户短代号指向上一条回复的哪个选项 |
| B-18 | 产出可溯源 | ④ 回合文本 | S6 | S2 | 可判「交付段有无『N 条有出处 / M 条无出处』」 |

**统计（v0.8.62）：18 条里 7 条有机制、11 条纯人工。**

| 强度 | 条数 | 规则 |
|---|---|---|
| S1 硬阻断 | 3 | B-05、B-14、B-16 |
| S2 拽回 | 1 | B-13 |
| S5 事后/形态 | 4 | B-02（形态判据）、B-09 / B-10（**在可选技能里，非必经点**）、B-15（v0.8.66 部分硬化，机器面已接电） |
| 纯人工 S6 | 10 | B-01 / 03 / 04 / 06 / 07 / 08 / 11 / 12 / 17 / 18 |

这个比例本身就是答案：**钩子不是万能的，它只能硬化「行为」，硬化不了「判断」。**
11 条里 10 条要求「怎么想」（是否真查了、是孤例还是模式），机器只能看文本；
唯一能再升一级的是 B-07（SessionStart 注入 handoff 首段，S4），但注入协议**尚未实测**，不做完不算数——
与其硬凑一个会误报的闸（误报会让人直接关掉钩子，代价大于漏判），不如在 `how` 里写清人工问法。

**强度不是登记出来的，是实测出来的。** 每条有机制的规则都在 `verify/rule_map.json`
里带 `strength` + `impl` + `proven_by`，由 `gate_scan --gate impl-reconcile` 双向对账：
映射说有人守、实物的 `# impl: B-xx Sn` 标记对不上，就红。

## 五、可落地但未做（按性价比排序）

1. ~~**B-13 → S2（Stop 拽回）**~~ **已落地**（`hooks/stop_guard.py`，v0.8.56）。
   关键发现：Stop payload 自带 `last_assistant_message`（本轮回复全文）与 `transcript_path`，
   判定不需要读 transcript 文件。判据走「断言词命中 + 全文零落点证据」双条件，
   任一证据（`rc=` / 退出码 / commit sha / 文件:行号 / `0 ✗` / `✓ N`）存在即放行——
   误报会让人关掉钩子，代价远大于漏判。
   防死循环两道：`stop_hook_active` 为真一律放行；同 session 连续拽回达 `MAX_RETRY` 次后放行并记 `gave_up`。

   **协议定版（两次对照实验，2026-11-14）**：拦住不让停有两写法，效果不一样。
   | 写法 | 结果 | 说明 |
   |---|---|---|
   | `exit 2` + stderr 文本 | **未拽回** | 回合照常结束，用户得自己再发一条才被拉回来 → 只算「事后可见」，S4 |
   | stdout `{"decision":"block","reason":...}` + `exit 0` | **拽回** | reason 作为 `Stop hook feedback` 注入，模型当场续写 → 真正的 S2 |
   探针日志佐证：脚本仅被调用 1 次（`stop_hook_active=false`、计数 1），说明是平台注入而非钩子二次执行。
   隐患登记：走 JSON 时平台注入后续写、再次 Stop 时 `stop_hook_active` 是否置真**未观测到**，
   故本机 `MAX_RETRY` 是主防线，不能只靠该字段。回归里已加一条「拽回走 JSON 而非 exit 2」，
   防以后有人好心改回去——那样钩子还在跑，语义却已降级。
2. ~~**B-05 → S1**~~ **已落地**（`hooks/guard_cmd.py` 的 G5/G6，v0.8.60）。
   命令侧 G5 拦 `git add` + 凭据名；写入侧 G6 拦 Write/Edit 到仓内凭据路径（仓外放行，
   交给 G5 在入库那刻挡）。两条都实测被平台阻断，probe 分别记 `+guard:G5` 与 `write-guard:G6`。
   **顺带修的真缺口**：`.gitignore` 原本没有 `.env`，`secret_scan.CRED_NAMES` 也不含它——
   于是 `git add -A`（不带文件名，G5 判不了）可以把仓内 `.env` 整包带走，两道闸都拦不住。
   已补 `.gitignore`（`.env` / `.env.*` / `credentials.*` / `*.pem|key|p12|pfx`，保留 `!.env.example`）
   并在 `CRED_NAMES` 加 `.env`，让「未忽略未追踪即红」接住批量 add。
   **误报已修（首版连拦三次）**：首版判据用「命令里有 add」+「命令里有凭据名」两个独立条件，
   于是「批量暂存 + 提交说明里提到 `.env`」也被判违例，挡住了正常工作流。已改为**一条**正则：
   凭据名必须紧跟在 add 之后、且与 add 之间无命令分隔符（`;` `&` `|` 换行）。13 条正反例全对。
   残余限制：把命令写进文本的场景（heredoc / 字符串）仍会被拦——钩子只能看文本，这层分辨不了，
   测试与文档里的样例一律用片段拼接绕开。
3. **B-07 → S4（SessionStart 注入）**：开机注入交接摘要首段。
   代价最低，但只是「提醒」级，不等于读了。
4. **B-09 → S1**：拦写产物区路径。需要先有一份「产物区路径清单」作为判据真源。

## 六、明确不做的

- **B-02 三态诚实加钩子**：正则判不了「这是不是真阳性」。硬加只会让模型学会换词绕过，
  真正的三态诚实只能靠产物审核与人工抽检。
- **B-01 语言加 Stop 判**：中文里夹 `token`、`JSON`、`commit sha` 是常态，误报率会高到
  让人关掉钩子——钩子被关掉等于全域失防，代价远大于收益。

## 七、维护

- 新增钩子规则后必须回填本表「当前强度」列，否则本表变成过时文档（病13 家族）。
- 判据三件套照旧：造违例 / 具体规则拦下 / 元变异（清空规则后违例必须溜过）。
- 本表与 `docs/工程纪律.md` §10（验证到末端）、`verify/tests/test_guard_cmd.py` 三处同源，
  改一处必须改另两处。
