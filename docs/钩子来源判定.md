# 钩子来源判定（2026-11-12 实查）

> **为什么单独写一份**：这个结论被误判过两次，两次都写进了文档。
> 把证据和判据固定下来，防止下一个人再凭印象改口。

## 一、现象

手机端会话执行一条含 `;` 或 `&&` 的 Bash 时被拦：

```
Error: PreToolUse:Bash hook blocked this tool call:
❌ 拦截: 一条 Bash 里检测到分号串联合令。
按 M-R123/R-BG03: 拆成多个单元动作用，或改用后台执行。
```

问题：这套钩子是**谁装的**？是不是 520pro 装的？是不是平台内建？

## 二、结论

**是旧生态备份仓 `DmaxPro908` 的 `hooks/chain_guard.py` 装的，与 520pro 无关，也不是平台内建。**

## 三、证据链（逐条可复核）

| # | 断言 | 证据 |
|---|---|---|
| 1 | 拦截逻辑在 `chain_guard.py` | `DmaxPro908/hooks/chain_guard.py:18-20`：`(r'&&', '链式 &&（合并多步）')`、`(r';\s*\S', '分号串联多条命令')`、`(r'\|\|', '\|\| 串联')` |
| 2 | 拦截文案逐字来自该文件 | 同文件 `:26`：`按 M-R123/R-BG03：拆成多个单动作调用，或改用后台执行。` |

## 四、两次误判（教训比结论更重要）

| 误判 | 错在哪 |
|---|---|
| 「手机端不跑钩子」（旧结论，已写入 MANIFEST / SOP） | 手机云沙箱**能跑** `PreToolUse`；旧结论只对"520 自己装钩子"成立，被推成了"平台不支持" |
| 「本机 settings.json 第 14-55 行挂着 PreToolUse，脚本不存在=死配置」 | 该文件总共 14 行、只有 `enabledPlugins`+`language`；读到的那份是 `/tmp` 里的临时 HOME |

两次的共同根因：**拿半份克隆 / 别人的 HOME 当"本机"，没先核对文件数与路径就下结论**。
机检对策已落在 `verify.sh` 的 H1 副本完整性基线（工作区文件数 < git 索引 85% 直接中止）。

## 五、对 520 的影响

- **无**：520 不装钩子，也不依赖钩子（`MANIFEST.no_hooks_dependency`）。
- 手机端的拦截行为来自那台设备上的旧生态残留，**改 520 不会改变它**；要去掉只能清该环境的 `~/.codebuddy/hooks` 与 `settings.json` 的 `hooks` 段。
- 反过来，这件事证明**手机端钩子机制可用**——如果将来要给手机端加判据闸，技术上没有障碍。
