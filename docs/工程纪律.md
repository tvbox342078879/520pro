## 1 · 关键词命中不能当结论（M-R12）

**旧实证**：旧生态 M13 把经验正文里的一句「把诊断转成可执行待办」判成了"真待办存在"——它命中的是
**描述这个动作的句子**，不是待办本身。

**纪律**：任何基于 grep / 正则 / 关键词的"有/无"判定，只能产出**候选**；要判真必须看结构
（JSON 字段、语法树、必填键齐全）。写判据时先自问：**"描述这个动作的句子会不会也命中？"**

**怎么查**：把待检文本里加一句"我应该扫描 X"，看判据会不会误报为"存在 X"。

## 2 · 检测器的静默失效比误报更危险（M-R32 + M-R63）

**旧实证**：旧生态 19 类检查器全报绿，同期实际有 315/439 个节点无主（71%）——**绿是扫描面窄的结果，不是没问题的结果**。

**纪律**：①检测器必须能区分「查了、确实没有」与「没查成」（三态，见 B-02）；
②检测器必须被证明覆盖它声称检测的每种形态，不能只覆盖"最容易写的那一种"。

**怎么查**：把输入清空、改成坏 JSON、或指向不存在的目录，看它是否仍报绿。仍绿 = 静默失效。

## 3 · 登记册的键必须是稳定指纹（M-R66）

**纪律**：白名单 / 豁免表 / 登记册 / 台账的键用**内容哈希**（sha1/sha256），禁用「文件:行号」——
改一行代码整表失配，而失配表现为"条目消失"，不是"键过期"。

**怎么查**：在同一文件上方插入一行空行，看登记册是否批量失配。

## 4 · 跨模块标识符必须从正本派生（M-R85）

**旧实证**：手抄的库 ID 两位颠倒，外部系统报的是「11510 not found」——人于是去重建库、去找新库，
真相只是两个字符错位。**手抄错的 ID 不会报语法错，只会报成外部系统故障。**

**纪律**：ID / 节点 ID / 路径 / 版本号一律从正本读或从正本派生，禁止在消费方写字面量。
这条与 B-08（正本入口）是同一族，B-08 管"动作走正门"，本条管"数据值不许手抄"。

## 5 · 关键纪律必须设在数据流必经点（M-R107）

**旧实证**：S153 的"提速入口"（预载经验 + 列雷区）明明写在输出里，照样被整轮绕过手写脚本，
同一件事慢 15.7 倍，历史招式被重新推导一遍。

**纪律**：以「提示 / 建议 / 文档」形式存在的纪律，等于没有纪律——调用方可以绕过。
要拦就拦在必经点：入口函数、提交前钩子、`verify.sh` 判据。

**520 的实际限制（诚实登记）**：本生态**不押 hook**（手机/云端不跑钩子），所以"必经点"只有两种：
入口函数内的闸、以及 `verify.sh` / CI。凡声称"已设卡"的，必须指到这两个之一；指不到的按"没有卡"算。

## 6 · 留痕数据禁按日期/键整体替换去重（M-R24）

**旧实证**：留痕类数据若按日期或 key 做"整体替换式去重"，同一天重跑就会把历史条目**连同其状态**
一起静默抹掉——看上去只是"少了几行"，实际是把处置记录删了。

**纪律**：留痕（日志、归档、收口记录）用**追加 + 稳定键去重**；禁止"整块重写"。

**怎么查**：看写盘代码是 `open(...,'w')` 整块 dump，还是追加合并；整块 dump 的留痕表要单独论证。

## 7 · 判据必须自证（M-R65 + M-R134/135/88/90）

**旧实证**：合成用例只能证明"逻辑自洽"，不能证明"对世界为真"；判据本身失效时，它给的绿最贵。

**520 自己的三个实例（2026-11-13，写台账四律判据时连续踩到）**：
1. **代理指标错位**：L4 首版用子串匹配找"退出码全局"，`_SEARCH_BOX_TPL` 里的 `SEA(RC)H` 被判中——误报 7 处。
   改成按 `_` 分词精确判才干净。
2. **判据形同虚设**：剥离注释时用 `' '.join(...)` 抹平了行结构，`^` 锚点失效，模块级 `_RC = 0` 漏判；
   **变异测试 C4 因此没翻红**——如果只看"真实仓全绿"就收工，这条判据是个摆设。
3. **检查器自指**：判据扫到了它自己文件里的反例文本（`sys.exit(x or 0)` 写在自己的 docstring 里）。

**纪律**：①禁用无因果的代理指标（时间窗代替 messageId、字符 n-gram 代替词项、子串代替分词）；
②判据落地必须做**变异自证**——拆掉被守护的实现，判据要**精确翻红**，不翻红即判据无效；
③自测的正例要抄真实样本原文，自编用例只证明逻辑自洽。

**怎么查**：新判据上线时，同时提交"变异用例"（`verify/tests/test_*.py` 里的红/绿对照）；
审查时先看变异用例，再看判据本身。
