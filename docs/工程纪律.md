## 1 · 关键词命中不能当结论（M-R12）

**旧实证**：旧生态 M13 把经验正文里的一句「把诊断转成可执行待办」判成了"真待办存在"——它命中的是
**描述这个动作的句子**，不是待办本身。

**纪律**：任何基于 grep / 正则 / 关键词的"有/无"判定，只能产出**候选**；要判真必须看结构
（JSON 字段、语法树、必填键齐全）。写判据时先自问：**"描述这个动作的句子会不会也命中？"**

**怎么查**：把待检文本里加一句"我应该扫描 X"，看判据会不会误报为"存在 X"。

## 2 · 检测器的静默失效比误报更危险（M-R32 + M-R63）

**旧实证**：旧生态 19 类检查器全报绿，同期实际有 315/439 个节点无主（71%）——**绿是扫描面窄的结果，不是没问题的结果**。

**纪律**：①检测器必须能区分「查了、确实没有」与「没查成」（三态，见 B-02）；
②检测器必须被证明覆盖它声称检测的每种形态，不能只覆盖"最容易写的那一种"。

**怎么查**：把输入清空、改成坏 JSON、或指向不存在的目录，看它是否仍报绿。仍绿 = 静默失效。

## 3 · 登记册的键必须是稳定指纹（M-R66）

**纪律**：白名单 / 豁免表 / 登记册 / 台账的键用**内容哈希**（sha1/sha256），禁用「文件:行号」——
改一行代码整表失配，而失配表现为"条目消失"，不是"键过期"。

**怎么查**：在同一文件上方插入一行空行，看登记册是否批量失配。

## 4 · 跨模块标识符必须从正本派生（M-R85）

**旧实证**：手抄的库 ID 两位颠倒，外部系统报的是「11510 not found」——人于是去重建库、去找新库，
真相只是两个字符错位。**手抄错的 ID 不会报语法错，只会报成外部系统故障。**

**纪律**：ID / 节点 ID / 路径 / 版本号一律从正本读或从正本派生，禁止在消费方写字面量。
这条与 B-08（正本入口）是同一族，B-08 管"动作走正门"，本条管"数据值不许手抄"。

## 5 · 关键纪律必须设在数据流必经点（M-R107）

**旧实证**：S153 的"提速入口"（预载经验 + 列雷区）明明写在输出里，照样被整轮绕过手写脚本，
同一件事慢 15.7 倍，历史招式被重新推导一遍。

**纪律**：以「提示 / 建议 / 文档」形式存在的纪律，等于没有纪律——调用方可以绕过。
要拦就拦在必经点：入口函数、提交前钩子、`verify.sh` 判据。

**520 的实际限制（诚实登记，2026-11-14 订正）**：旧结论「手机/云端不跑钩子」**已作废**——手机端会话实测能跑钩子（`commit-msg` 于 2026-11-14 在手机端会话拦截过一次错误提交；证据见 `docs/钩子来源判定.md`）。520 现已装 `pre-commit` + `commit-msg` 双钩子，但判据主落点仍是 `verify.sh`——钩子可 `--no-verify` 绕过，只算必经点之一。"必经点"共三种：入口函数内的闸、提交钩子、`verify.sh` / CI。凡声称"已设卡"的，必须指到这三者之一；指不到的按"没有卡"算。

## 6 · 留痕数据禁按日期/键整体替换去重（M-R24）

**旧实证**：留痕类数据若按日期或 key 做"整体替换式去重"，同一天重跑就会把历史条目**连同其状态**
一起静默抹掉——看上去只是"少了几行"，实际是把处置记录删了。

**纪律**：留痕（日志、归档、收口记录）用**追加 + 稳定键去重**；禁止"整块重写"。

**怎么查**：看写盘代码是 `open(...,'w')` 整块 dump，还是追加合并；整块 dump 的留痕表要单独论证。

## 7 · 判据必须自证（M-R65 + M-R134/135/88/90）

**旧实证**：合成用例只能证明"逻辑自洽"，不能证明"对世界为真"；判据本身失效时，它给的绿最贵。

**520 自己的四个实例（2026-11-13，写台账四律判据时连续踩到）**：
1. **代理指标错位**：L4 首版用子串匹配找"退出码全局"，`_SEARCH_BOX_TPL` 里的 `SEA(RC)H` 被判中——误报 7 处。
   改成按 `_` 分词精确判才干净。
2. **判据形同虚设**：剥离注释时用 `' '.join(...)` 抹平了行结构，`^` 锚点失效，模块级 `_RC = 0` 漏判；
   **变异测试 C4 因此没翻红**——如果只看"真实仓全绿"就收工，这条判据是个摆设。
3. **检查器自指**：判据扫到了它自己文件里的反例文本（`sys.exit(x or 0)` 写在自己的 docstring 里）。
4. **同名文件蹭绿**（同日稍晚，写 B-07 接手条款判据时）：首版只 `grep 'handoff_latest.md'`，
   手机指令第 69 行那句「交接账目在桌面 `docs/handoff_latest.md` 维护」——它是解释 B-14 为何
   不入硬轨的**理由**，不是"去读摘要"的**动作**——把变异蹭成了假绿：删掉真动作句，判据照样 ✓。
   改为要求「读」与文件名**同行且相邻**（`re` 双向前后 60 字符），才把"提到文件"和"要求读文件"分开。

**纪律**：①禁用无因果的代理指标（时间窗代替 messageId、字符 n-gram 代替词项、子串代替分词）；
②判据落地必须做**变异自证**——拆掉被守护的实现，判据要**精确翻红**，不翻红即判据无效；
③自测的正例要抄真实样本原文，自编用例只证明逻辑自洽；
④**存在性判据必须自己声明它不证明什么**（如"条款在位"≠"agent 真读了"），别让读者把绿当因果。

**怎么查**：新判据上线时，同时提交"变异用例"（`verify/tests/test_*.py` 里的红/绿对照）；
审查时先看变异用例，再看判据本身。

## 8 · 状态进 git 前过「四条件」（908 蓝图 §4.5 · 2026-11-13 采纳）

**旧实证**：908 旧生态把本地 .codebuddy 当数据库，越堆越大（700MB+，其中 190MB 是框架
运行时产物），客户端一次性全量加载 → 越用越卡（P0105）。重做蓝图定下 git-as-DB 边界。

**纪律**：一个新的状态文件**只有同时满足**「低频写 + 读多 + 小文件 + 结构化」四条件
才进 git；违反任一必须分层（高频→内存/本地临时，大对象→资料库/云端，敏感→凭证管理器，
永不进库）。心跳/计数器/高频计数不进 git。

**怎么查**：①建状态文件前自问四条件，答不上就不进库；②机检已落地——`secret_scan.py`
的大文件闸（>10MB 即红，`verify/tests/test_secret_scan_size.py` 4 用例变异回归），
敏感面由九类凭证扫描同一闸覆盖。

## 9 · 先查再造（2026-11-14 采纳）

**旧实证**：2026-11-14 一轮会话里连提四个「新机制」——handoff 自动生成器、记忆条目加
`disclosure` 必填字段、新建 `Lesson` 存储、跨 session 限流。**四个全被否**，其中两个
（经验四层、`docs/registry.md` 真源登记）**现有机制里本来就有**，属于没查就发明：
- `Lesson` 存储 → `docs/通病台账.md` 已有病历格式 + 复发次数 + `candidate→active` 规则；
- 真源重复 → `docs/registry.md` 第 4 行早写着「新增一类事实在本表加一行，不许在别处平行定义」。

代价是四轮往返才收敛，且每轮都在"发明→被否→再发明"里空转。

**纪律**：提方案前过**四查**——`docs/registry.md`（有没有现成真源）/ `docs/工程纪律.md`
（有没有现成条文）/ `docs/通病台账.md`（是不是踩过的病）/ `verify/`（有没有现成判据）。
四查皆无才允许新建，且须逐项写明"为什么不复用"。**能扩就不新建，能复用就不扩。**

**怎么查**：机检落点是提交信息 `Reuse:` 行（`hooks/commit-msg` ④ 段）——
① 声称新建必须写「已查」+ 各自理由；② 声明的文件名必须与 `git diff --cached --diff-filter=A`
逐个对上；③ 写「新建 0」却被查出新增了 `docs/*.md`／`verify/*.py`／`hooks/*` 直接拒收。
变异回归见 `verify/tests/test_commit_fields.py` 例 4/例 5。

**诚实边界**：拦不住「想」，只拦得住「写」。方案在对话里被发明时机器看不见，
落地那一刻才看得见。这道闸管的是「发明的落地成本」，不是「发明的念头」——
不要把它说成后者，那才是纸面承诺。
