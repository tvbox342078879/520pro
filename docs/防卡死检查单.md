# 防卡死检查单（真源）

> **真源声明**：本文件是 520pro 防卡死口径的唯一真源（M1）。机检判据在 `verify.sh`（守本文件存在性 + 四条硬判据），执行闸在 `hooks/task_wait_guard.py` / `hooks/guard_cmd.py` / `hooks/git_push_safe.sh`。改口径先改这里（M5 连带跑 verify）。
> **来源**：两案合并——①2026-11-17 防卡死盘点（挂死主干已覆盖，缺会话等待闸/自锁判据/传播判据）；②flow_gate 自锁事故复盘（治理机制锁死治理对象，四层死锁，只能用户环境层解锁）。

## 一、四类死法与既有防线

| 死法 | 典型场景 | 防线（落点） |
|---|---|---|
| 挂死 | 前台死等、无限重试、批量跑死 | git_push_safe 5 次+单次 300s+终验；sync fetch 60s；G7 前台 sleep≥30s 硬拦；G8 工具洪水闸；全仓循环有界 |
| 等待死 | 会话卡在 block=true 等后台转圈 | **task_wait_guard.py（v0.8.79 新增）**：同任务第 3 次阻塞等待 deny，提示改非阻塞 |
| 自锁死 | 治理钩子 deny-all 锁死会话、阶段机推不动 | guard_cmd 是定向拦截非 deny-all、stop_guard fail-open；**本检查单防将来装闸自锁** |
| 传播死 | 钩子更新到不了旧设备，旧设备被旧钩子咬 | git 自愈通道判据（verify 行为级测试）：git 同步命令恒不命中任何 G 闸 |

## 二、设计总原则

> **任何锁必须自带不依赖外部条件的自救出口**——逃生口选在被锁实体仍可达的层、放在闸门最上游（放自检之后=没放）、死状态自动过期。

## 三、装任何闸门前过一遍（检查单）

1. □ 管理动作（init/advance/status/自检/自测/非阻塞读取）是否豁免自身约束？
2. □ 逃生口是否设在被锁实体仍可达的层？（会话锁死时只剩对话层）
3. □ 自救命令（git pull/fetch/checkout/restore/switch/merge/rebase/clone）是否放在闸门最上游、deny-all 生效前？
4. □ 死状态是否自动过期（如等待计数 >1h 清零、化石流程 >24h 归档），还是永久锁门？
5. □ 钩子更新能否到达所有已接线设备？不能的话旧设备有无本机自救通道（git 拉取豁免）？
6. □ 修复件复活是否走 owner 显式授权，禁静默接活链？
7. □ 全部判据是否配双向自测（违规拦得住、合规不误拦）？

## 四、硬判据落点（机检）

| 判据 | 落点 | 防 |
|---|---|---|
| 本文件存在性 | verify.sh | 检查单成死文件 |
| task_wait_guard.py 在位+语法+settings 注册 | verify.sh | 等待闸失装 |
| git_push_safe SSH 段 timeout 300 | verify.sh | SSH 兜底段挂死 |
| verify.sh 自身总时限 900s（exec timeout 自包裹） | verify.sh 顶部 | 判据链本身慢死 |
| git 自愈通道行为级判据（8 条同步命令调 check() 零命中） | verify.sh | 将来加闸误伤自救通道 |

## 五、三态边界

- task_wait_guard 的 **PreToolUse·TaskOutput matcher 运行时是否真触发**：配置层已注册（install.sh 幂等追加 + verify 判据守在位），运行时触发依赖平台对非 Bash 工具的 PreToolUse 支持——**配置确定、运行未测**，首真实阻塞等待时看 deny 提示即实证。
- task_wait_guard fail-open：脚本异常 exit 0 放行，不会重演 deny-all 自锁。
