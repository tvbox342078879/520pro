# artifact-store · 本地轻量化总闸

> **第一动作（自省锚点）**：命中触发词后**先读本技能全文**再动手；不许看见触发词/脚本就直接执行——
> 判据在本文件，不在记忆里；跳过本文件动手，等于没有判据。

> 通用铁律由 `core-8.md` + 薄壳 + `zh-style.md` 三通道全局强制，本技能直接继承、不重复声明（见 SOP 20.9 / M2）。

## 何时使用
- 触发词（唯一真源）：手机卡 / 瘦身 / 清理产物 / 记忆归档 / 本地清理 / 手机越用越卡 / 本地太重了 / 记忆太多了 / 旧对话清一下 / 归档
- 用户反馈手机变卡、本地堆积过多，或要求瘦身 / 归档 / 清理时。

## 1. 先认清根因（官方一手，非社区推断）
依据 CodeBuddy Code **CLI Best Practices** + **v2.51.0 发布说明** + **Memory 文档**：
- 上下文窗口快速填满（含全部对话、每读过的文件、每条命令输出），性能线性下降；
- 四层记忆文件全部启动时自动注入，记忆目录无管控会无限增长；
- 本地产物 / 缓存 / 旧会话不清理，搜索、历史、切换变慢。

**总原则**：本地只留热/必要的，冷的归档资料库、检索走远程；记忆优先用官方原生按需加载与自动清理，不重复造轮子。

## 2. 四类堆积：官方原生解法优先，本技能兜底

| 堆积类 | 官方原生解法（优先） | 本技能/治理层职责（兜底） | 协同 |
|---|---|---|---|
| ① 产物 | — | 本地 LRU 只留 2 轮，更早归档资料库（manifest:来源/时间/类型）+ 删本地 | 独立负责 |
| ② 记忆 | **v2.51.0 记忆目录摘要（按需加载）+ 自动清理（随会话历史，复用保留期）** | 仅对**超大主题文件**兜底归档资料库经验层；本地不另建冷归档索引 | `skill-evolution` |
| ③ 会话 | **`/clear`（清上下文保设置）+ 移动端删/归档旧会话（≡→任务历史→垃圾桶）** | 一事一话；重要内容存资料库，对话用完即弃 | 用户纪律 |
| ④ 上下文窗口 | **`/clear` 纪律 · Subagents 独立上下文 · `/compact` 定制压缩 · 条件规则 `paths` · parentDiscovery 关闭 · 不盲目拉大窗口（200K 够用）** | 靠 `zh-style.md` §8 立纪律，本技能只监测、不强制 | `zh-style` |

> ②记忆与③会话**不删真源**，只把"冷/旧/超大"挪出本地加载路径；④是官方机制 + 规则纪律，本技能不越界。

## 3. 工作流
1. 扫描本地四类堆积：产物目录 / 记忆索引 / 会话台账 / 上下文体积。
2. 产物：最近 2 轮留本地，更早 → 资料库（manifest）+ 删本地。
3. 记忆：优先官方原生（目录摘要按需加载 + 自动清理）；仅当单主题文件过大，才兜底归档资料库经验层、本地仅留指针（**不重建摘要机制**）。
4. 会话：识别可归档旧对话 → 重要内容存资料库 → 建议用户用 `/clear` 或移动端删/归档会话。
5. 上下文：提示走 `zh-style.md` §8（/clear · Subagents · /compact · 条件规则 · parentDiscovery）。
6. 检索：本地未命中 → 资料库远程索引（RAG）→ 命中可拉回。

## 4. 边界
- 不碰源码/规则（git 真源，不归档删除）。
- 删除本地前**必须**确认已归档成功，否则中止并报"无法判定"。
- 不删除远端任何东西；不替用户决定清哪条对话（只建议 + 待确认）。
- 上下文纪律属 `zh-style.md` §8（官方机制为主），本技能只监测、不强制。

## 5. 官方能力对齐清单（不重复造轮子）
- ❌ 不自建"记忆冷归档索引" → 用 v2.51.0 原生记忆目录摘要 + 自动清理。
- ❌ 不强制 `/clear` → 在 `zh-style.md` §8 立纪律，并引导用户移动端删/归档会话。
- ✅ 只做官方未覆盖的：产物 LRU 归档、超大主题文件兜底、资料库检索编排。

## 6. SOP 对齐
- 第 18 章 资料库联动：产物/记忆按类型自动归类资料库。
- 第 17 章 经验复用：记忆清理不丢经验，靠官方摘要/自动清理 + 资料库兜底。
- 第 16 章 唯一真源：归档前先确保已进 git 或资料库。
- 第 19 章 跨端：资料库云端可搜，手机/桌面一致，本地不堆重。

## 7. 执行体（`scripts/artifact.py`）

> v1.0.3 起本技能带执行体：**扫描与预览走脚本，不许照本文自己编**。脚本只读，不移动、不删除任何文件。

```bash
python3 scripts/artifact.py scan          # 只看计划，不动文件
python3 scripts/artifact.py scan --json   # 机器可读，供巡检/回归消费
python3 scripts/artifact.py self-check    # 用构造样本验证分类器（8 例）
```

它解决三件靠文字判不了的事：

| 靠文字判不了 | 脚本怎么判 | 实测依据 |
|---|---|---|
| 「产物」的边界 | 含 `.git` 的子树整体标保护，整个不参与归档 | 本机某会话 25.1M 里 22.6M 是一个仓库副本，按 mtime 清会删掉工作副本 |
| 「2 轮」的判据 | 轮次 = 会话目录，不是文件 mtime | 同一会话里最老的文件也属于本轮产物，按天清会清掉当天要用的 |
| 符号链接逃逸 | `followlinks=False` + 逐项 `islink` 跳过 | 与 import_guard 的 TOCTOU 同类 |

三态输出：`OK 有计划` / `NOOP 无需归档` / `UNKNOWN 无法判定`（退出码 2，绝不装绿）。

**删除永远由人执行**：脚本只出计划，人看过计划自己敲命令；脚本里不存在任何删除分支。
