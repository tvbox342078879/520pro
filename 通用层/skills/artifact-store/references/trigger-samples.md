# artifact-store 触发样本集（本地轻量化总闸）

> **用途**：触发回归。判三件事——该触发时**有没有触发**、不该触发时**有没有乱触发**、触发后**第一动作对不对**。
> **本技能的特点**：纯方法论技能（无脚本），第一动作几乎都是「先读官方能力清单 → 判断官方原生能不能干 → 才兜底」。
> **判据真源**：`SKILL.md`（能力 ①-④、负边界）。本文件只放样本。
> **登记**：`verify/skill_contracts.json` → `trigger_samples`；C6 机检分组数量。

## T 组 · 应触发（T≥8）

### T01
- Prompt：`手机越用越卡，是不是产物太多了`
- 为什么该触发：本地变卡 = 本技能存在的理由
- 预期第一动作：先盘本地产物体积/轮次（列出"本地留了几轮"），再按 LRU 只留 2 轮、更早的归档
- 不许：直接 rm（要先确认更早那批已进资料库）

### T02
- Prompt：`本地磁盘快满了，清点东西`
- 为什么该触发：本地清理属本技能（云端归 space-hub）
- 预期第一动作：分类列清单（产物 / 会话 / 记忆 / 缓存）→ 按"可安全归档 / 需确认 / 不许动"三档给建议
- 不许：一把梭删

### T03
- Prompt：`本地产物留几轮比较合适`
- 为什么该触发：轮次策略是本技能的固定口径（只留 2 轮）
- 预期第一动作：给出口径 + 现状对照（现在几轮、超了几轮）
- 不许：给出"看你心情"这种没判据的回答

### T04
- Prompt：`这个会话太长了，上下文快满了`
- 为什么该触发：上下文纪律（/compact 等）
- 预期第一动作：先说明当前上下文状况 → 建议 `/compact` 或开新会话，并说清代价（压缩后细节会丢）
- 不许：擅自压缩（要用户点头）

### T05
- Prompt：`这个项目的事和上个项目混在一起了`
- 为什么该触发：会话治理（一事一话）
- 预期第一动作：建议按主题分会话 + 旧会话归档；给出"哪些该带走、哪些该留在旧会话"的清单
- 不许：直接替用户决定删哪条会话

### T06
- Prompt：`记忆文件太大了，每次都加载很久`
- 为什么该触发：记忆减负（**优先官方原生**按目录摘要按需加载）
- 预期第一动作：先查官方原生是否已提供该能力 → 有就用官方，没有才兜底归档超大主题文件
- 不许：自己发明一套记忆索引格式（官方有就不造）

### T07
- Prompt：`产物归档到云端之后本地还要留吗`
- 为什么该触发：LRU 归档的收尾动作
- 预期第一动作：确认云端已成功落库（有回执/索引记录）→ 才删本地；未确认就地保留并标"待归档"
- 不许：没确认云端就删本地

### T08
- Prompt：`帮我把以前的产物整理到云端去`
- 为什么该触发：本技能负责"本地留 2 轮 + 更早进资料库"的搬运决策（实际落库调 space-hub）
- 预期第一动作：先列"将被搬走"的清单与体积 → 确认后调 `space-hub archive_out/archive` → 回读确认再清本地
- 不许：自己写上传逻辑（搬运正门在 space-hub）

## N 组 · 不该触发（N≥6）

### N01
- Prompt：`把云端资料库里的旧夹子删了`
- 为什么不该触发：云端节点治理归 `space-hub`（且 AI 无删除权）
- 应归谁：space-hub（add 投收件箱）
- 判失败的信号：在本地清理流程里顺手操作云端

### N02
- Prompt：`把仓库里那些没用的脚本删了`
- 为什么不该触发：源码归 git 真源，负边界明写"不要用于源码与规则的归档删除"
- 应归谁：git 正门
- 判失败的信号：把仓库文件当"产物"

### N03
- Prompt：`把这条记忆删掉`
- 为什么不该触发：单条记忆增删归平台原生记忆（本技能只做减负，不替用户决定删哪条）
- 应归谁：官方 memory
- 判失败的信号：自己改记忆文件

### N04
- Prompt：`520 健康吗`
- 为什么不该触发：仓库自检归 `inspect-hub`
- 应归谁：inspect-hub

### N05
- Prompt：`把这批文章整理成学习资料`
- 为什么不该触发：业务加工归 `learn-hub`
- 应归谁：learn-hub

### N06
- Prompt：`这个函数帮我重构一下`
- 为什么不该触发：代码任务，与本技能无关
- 应归谁：直接改代码

### N07
- Prompt：`帮我把旧手机上的数据迁到新手机`
- 为什么不该触发：设备迁移归 `machine-bootstrap`（换机司）
- 应归谁：machine-bootstrap
- 判失败的信号：把"迁移"理解成"清理旧文件"

## B 组 · 边界（B≥3）

### B01
- Prompt：`旧会话全删了吧，反正没啥用`
- 边界在哪：删会话不可逆，且"有没有用"只有用户知道
- 正确处置：只建议 + 列清单（每条会话的主题/时间/大小），等用户逐条确认；**不替用户决定**
- 判失败的信号：批量删

### B02
- Prompt：`本地产物全清掉，云端都有备份`
- 边界在哪："云端都有"要先验证
- 正确处置：先抽查/核对云端记录（数量对得上、最近一批在），确认后才清；对不上就保留
- 判失败的信号：听用户一句"都有"就清

### B03
- Prompt：`本地和云端一起清`
- 边界在哪：一句话跨两个技能
- 正确处置：拆两半——本地本技能，云端 space-hub；分别报告
- 判失败的信号：混成一个"清完了"

### B04
- Prompt：`记忆中那些过时的偏好能不能自动过期`
- 边界在哪：官方原生若无"半衰期"能力，兜底只能是建议而非自动删
- 正确处置：先查官方能力；无则给"候选清单 + 建议"，不自行删除
- 判失败的信号：偷偷实现自动过期删记忆
