# inspect-hub 触发样本集（520 巡检司）

> **用途**：触发回归。判三件事——该触发时**有没有触发**、不该触发时**有没有乱触发**、触发后**第一动作对不对**。
> **怎么用**：逐条读 Prompt，先判"该不该进巡检司"，再核"第一动作"是否一致。
> **判据真源**：`SKILL.md` + `scripts/inspect_registry.json`（面目录与阈值）。本文件只放样本。
> **登记**：`verify/skill_contracts.json` → `trigger_samples`；C6 机检分组数量。

## T 组 · 应触发（T≥8）

### T01
- Prompt：`520 体检`
- 为什么该触发：最直白的触发词
- 预期第一动作：`python3 scripts/inspect_hub.py run`（一面不少地跑，产出 dashboard.html 并拉到眼前）
- 不许：只跑一两面就下"健康"结论

### T02
- Prompt：`拉下面板我看看`
- 为什么该触发：「拉面板」是本技能固定能力（单文件 dashboard，八卦八门）
- 预期第一动作：`inspect_hub.py run` → 报告面板路径并打开
- 不许：临时手搓一个 html 糊弄（模板在 `scripts/dashboard_template.html`）

### T03
- Prompt：`哪里没检查`
- 为什么该触发：问的是**覆盖面**，正是登记册驱动的灰面语义
- 预期第一动作：`run` 后看灰色面（登记了但检查器未实现/失灵）→ 明确列出"没查的"和"查不了的"
- 不许：把灰面算成通过

### T04
- Prompt：`有什么遗留没处理`
- 为什么该触发：「遗留登记」是八面之一
- 预期第一动作：`run` → 读遗留登记面 → 逐条给"归谁处置"
- 不许：只报总数不给清单

### T05
- Prompt：`巡检引擎自己是不是好的`
- 为什么该触发：问引擎健康 = self-check，不是业务面
- 预期第一动作：`inspect_hub.py self-check`（引擎/登记册/模板三项预检）
- 不许：拿 run 的成功当引擎健康的证据

### T06
- Prompt：`面板全是绿的，是真的吗`
- 为什么该触发：质疑假绿 = 对抗自测
- 预期第一动作：`inspect_hub.py adversarial`（逐门造脏断言必翻红；临时 clone 不污染仓库）
- 不许：口头保证"这闸肯定有效"（没变异测试就没有证据）

### T07
- Prompt：`520 最近有没有变差`
- 为什么该触发：「环比指纹」能力——只看变化
- 预期第一动作：`run` → 与 `findings_history.json` 对比 → 只报新增/消失项
- 不许：把历史老问题当"这次新发现"

### T08
- Prompt：`inspect 一下，顺便看看规则生效没`
- 为什么该触发：显式 inspect + 指定面（规则生效是八面之首）
- 预期第一动作：`run`，重点看"规则生效"面（core-8 是否真的被加载/生效）
- 不许：跳过该面只报其他面

## N 组 · 不该触发（N≥6）

### N01
- Prompt：`看看 TVBox 上游那几个作者仓库还活着吗`
- 为什么不该触发：盯**外部上游**归 `probe-hub` 探源司；本技能明确"盯 520 自家健康"
- 应归谁：probe-hub（monitor check / diff）
- 判失败的信号：用巡检面去扫上游仓库

### N02
- Prompt：`技能契约有没有不合规的`
- 为什么不该触发：逐项机检归 `verify/skill_contract_check.py`（确定性脚本，不是巡检面）
- 应归谁：verify/skill_contract_check.py
- 判失败的信号：把契约检查塞进巡检面板当一面

### N03
- Prompt：`面板说 xxx 有问题，你直接帮我修了`
- 为什么不该触发：本技能**只体检不动刀**（修由各技能正门做）
- 应归谁：对应技能的正门（如 space-hub / probe-hub）
- 判失败的信号：巡检过程中顺手改被检对象

### N04
- Prompt：`资料库乱不乱，帮我理理`
- 为什么不该触发：云端空间治理归 `space-hub` 库务司
- 应归谁：space-hub（census / classify）
- 判失败的信号：用 census 冒充巡检

### N05
- Prompt：`跑一下 verify.sh 看判据`
- 为什么不该触发：直接跑脚本即可，用户没要体检/面板
- 应归谁：直接 `bash verify.sh`
- 判失败的信号：为一条命令去加载整套巡检

### N06
- Prompt：`把这批文章整理成学习资料`
- 为什么不该触发：学习资料业务归 `learn-hub`
- 应归谁：learn-hub
- 判失败的信号：把业务加工当巡检

## B 组 · 边界（B≥3）

### B01
- Prompt：`检查器跑不起来，应该没啥问题吧`
- 边界在哪：检查器失灵 ≠ 没问题
- 正确处置：该面记**「无法判定」**并在面板标灰，明确告知"这一面没查到，不是通过"；绝不装绿（三态铁律）
- 判失败的信号：异常被 catch 后跳过、面板仍显示绿

### B02
- Prompt：`体检发现问题了，顺手都改了吧`
- 边界在哪：巡检的职责边界是"只体检"
- 正确处置：出清单 + 每项给"修复正门"，由用户点头后再逐项走各自技能修
- 判失败的信号：巡检脚本里出现写操作

### B03
- Prompt：`体检结果发我一份 Word`
- 边界在哪：本技能产出是**单文件 html 面板**
- 正确处置：面板即交付；确需 Word 另行走文档技能，不在巡检里塞导出器
- 判失败的信号：为格式需求给巡检加一堆导出分支

### B04
- Prompt：`只跑密钥那一面就行，别的不用`
- 边界在哪：单面跑会破坏"整体健康"语义
- 正确处置：可以单面看，但结论必须声明"仅该面，其余未查"，不得输出总体健康判断
- 判失败的信号：单面绿 → 报"520 健康"
