# inspect-hub · 故障排查（按症状查）

> **怎么用**：巡检司自己的坑几乎都是"**看起来绿了，其实没查**"。
> 机检：`verify/tests/test_troubleshoot.py` 要求 ≥5 条真实条目。

## 1. 某一门显示「无法判定」而不是红/绿

- **先查**：`--target` 指的是不是 520pro 仓库根；该门的扫描器/数据文件在不在。
- **怎么办**：修好输入再跑；修不好就让它保持灰——**灰是结论**（"查不了"），不是待办。
- **别做**：不要把 unknown 手工改成 green；也不要把 unknown 报表成"通过"（三态铁律）。

## 2. 面板打开是空白 / 数据是上一次的

- **先查**：`run` 是否真的产出了新的 `dashboard.html`（看文件修改时间）；模板是否被改坏。
- **怎么办**：先跑 `self-check`（模板可渲染是它的三项之一）；再重跑 `run --out <目录>`。
- **别做**：不要直接编辑 `dashboard.html`——它是产物，下次 run 会覆盖。

## 3. 八门里有「⚪ 在册待补」的灰门

- **先查**：`inspect_registry.json` 里该门 `impl` 是不是 null。
- **怎么办**：要么补实现（登记册加 impl，零改引擎），要么明确删掉这门并说明理由。
- **别做**：不要留着一门永远灰的检查——时间久了没人知道它到底查没查。

## 4. 环比标记乱了（🆕/✅/♻️ 与预期不符）

- **先查**：`findings_history.json` 是不是被手工改过或被当成"正本"提交了。
- **怎么办**：它是运行时数据（RUNTIME_FILES），删掉后下次 run 重建；历史丢了不影响本轮结论。
- **别做**：不要拿它当审计证据——真证据在每轮的输出与 git 历史里。

## 5. 自检通过，但体检结论明显不对

- **先查**：`self-check` 只证明"引擎/登记册/模板健康"，**不证明巡检结果对**；看具体门的证据字段。
- **怎么办**：挑一门手工复核（按它的 impl 命令跑一次），对不上就是该门判据有问题。
- **别做**：不要用"self-check 通过"替代"巡检通过"——两者是不同层次。
