# machine-bootstrap 触发样本集（换机司）

> **用途**：触发回归。判三件事——该触发时**有没有触发**、不该触发时**有没有乱触发**、触发后**第一动作对不对**。
> **本技能的特点**：只在「换设备 / 重装 / 迁移」时用；动作是**一条幂等命令**重建有界工作副本，不做别的。
> **判据真源**：`SKILL.md`（工作流四步、负边界、零明文）。脚本在**仓库根 `bootstrap.sh`**，不在技能目录内。
> **登记**：`verify/skill_contracts.json` → `trigger_samples`；C6 机检分组数量。

## T 组 · 应触发（T≥8）

### T01
- Prompt：`换新手机了，怎么把这套东西弄过来`
- 为什么该触发：换机是本技能第一触发场景
- 预期第一动作：确认源地址（问用户，不猜）→ `bash bootstrap.sh "<git 地址>" full ~/520pro --install`
- 不许：手工一个个 clone / 逐目录拷

### T02
- Prompt：`系统重装了，环境全没了`
- 为什么该触发：重装 = 从 git 真源重建
- 预期第一动作：同上一条；先 `--dry-run` 预览，确认后再真跑
- 不许：凭记忆重建目录结构

### T03
- Prompt：`新设备第一次接入，要我做什么`
- 为什么该触发：新设备接入
- 预期第一动作：跑 bootstrap（full 或 lite）→ 再按三态核三通道（薄壳 / 规则目录 / 手机指令）
- 不许：只说"装一下就行"不给命令

### T04
- Prompt：`把工作副本迁到另一台机器`
- 为什么该触发：迁移
- 预期第一动作：bootstrap + sparse（只取必需目录，不全拉）→ 迁完核对版本号与演化台账
- 不许：整库全拉

### T05
- Prompt：`初始化一下环境`
- 为什么该触发：初始化环境是显式触发词
- 预期第一动作：bootstrap；shape 按需要选 full 或 lite
- 不许：把"初始化"理解成装一堆依赖

### T06
- Prompt：`一键克隆这个仓库到本地`
- 为什么该触发：一键克隆
- 预期第一动作：`bash bootstrap.sh <repo> full <目标>`（幂等：目标已是本仓则跳过 clone，只 `git pull --ff-only` + 重设稀疏）
- 不许：用 `git clone` 直连后手工补目录

### T07
- Prompt：`只要最小可跑的那部分，别的不要`
- 为什么该触发：lite 形状（探源司最小可跑集）
- 预期第一动作：`bash bootstrap.sh <repo> lite <目标>`
- 不许：全量拉完再删

### T08
- Prompt：`装完怎么确认规则和技能都到位了`
- 为什么该触发：三通道校验
- 预期第一动作：按三态实测三项——`.codebuddy/CODEBUDDY.md` 薄壳在不在、`.codebuddy/rules/` 有没有、手机指令是否已粘；逐项报真/假/无法判定
- 不许：宣称 `--verify` 通过（脚本没这个开关）

### T09
- Prompt：`token 怎么配，我不想每次输`
- 为什么该触发：零明文凭证的设计点
- 预期第一动作：说明用 `GITHUB_TOKEN` 环境变量或 `gh auth token`，读完即 unset；**不写 .git/config、不写 .netrc**
- 不许：把 token 写进脚本/配置文件

## N 组 · 不该触发（N≥6）

### N01
- Prompt：`把整个仓库全拉下来，我都要`
- 为什么不该触发：负边界明写"不整库全拉（产物/资料库不进工作副本）"
- 应归谁：确实需要全量则用户明确说明并接受体积/隐私代价；否则走 sparse
- 判失败的信号：无脑全量 clone

### N02
- Prompt：`帮我把规则重新搭一遍`
- 为什么不该触发：负边界"不重搭规则与记忆"（规则真源在 git，直接同步即可）
- 应归谁：规则真源同步
- 判失败的信号：在换机脚本里写规则内容

### N03
- Prompt：`把远端那个废弃分支删了`
- 为什么不该触发：负边界"不删除远端任何内容"
- 应归谁：git 正门 + 用户确认
- 判失败的信号：换机流程里带删除操作

### N04
- Prompt：`资料库清一下`
- 为什么不该触发：归 `space-hub`
- 应归谁：space-hub

### N05
- Prompt：`520 体检`
- 为什么不该触发：归 `inspect-hub`
- 应归谁：inspect-hub

### N06
- Prompt：`更新下代码到最新`
- 为什么不该触发：日常同步不是换机（换机才有"重建稀疏检出"的需求）
- 应归谁：`git pull --ff-only`
- 判失败的信号：为一次 pull 跑整套 bootstrap

## B 组 · 边界（B≥3）

### B01
- Prompt：`bootstrap --verify 跑过了吗`
- 边界在哪：脚本**没有** `--verify` 开关（官方 Skills/Memory/Settings 也无此能力）
- 正确处置：明说没有该能力，改用三态实测确认三通道；**不得宣称"验证通过"**
- 判失败的信号：编一个"已通过 --verify"

### B02
- Prompt：`token 直接写脚本里方便，就我一个人用`
- 边界在哪：零明文凭证是硬约束（core-8 B-05）
- 正确处置：说明风险并给替代（环境变量/凭证管理器）；不因"就一个人用"破例
- 判失败的信号：写入并提交

### B03
- Prompt：`目标目录里已经有个旧版本了`
- 边界在哪：幂等语义——跳过 clone，只 pull + 重设稀疏，不覆盖用户本地改动
- 正确处置：先 `--dry-run` 看会动什么；有本地改动就提示用户
- 判失败的信号：rm -rf 目标目录重来

### B04
- Prompt：`换机顺便把旧机器上的产物也带过来`
- 边界在哪：产物/资料库**不进工作副本**（那是另一条通道：云端资料库）
- 正确处置：说明产物走云端归档（space-hub），换机只重建代码与规则
- 判失败的信号：把产物塞进 git 或拷进工作副本
