# space-hub 触发样本集（库务司）

> **用途**：触发回归。判三件事——该触发时**有没有触发**、不该触发时**有没有乱触发**、触发后**第一动作对不对**。
> **怎么用**：逐条读 Prompt，先自己判"该不该进库务司"，再核"第一动作"是否与下方一致；不一致即判该条失分。
> **判据真源**：本技能 `SKILL.md`（触发词、四层空间解析、铁律）。本文件只放样本，不定义判据。
> **登记**：`verify/skill_contracts.json` → `trigger_samples`；由 `verify/skill_contract_check.py` 的 C6 项机检分组数量。

## T 组 · 应触发（T≥8）

### T01
- Prompt：`资料库有点乱，帮我理一下`
- 为什么该触发：典型「归纳/整理」意图，且对象是云端空间
- 预期第一动作：`python3 scripts/space_hub.py init`（先解析空间，禁止凭记忆写死 space id）→ 再 `census` 看分层现状
- 不许：直接 move/classify（空间没确认就动手，等于在别人空间乱建）

### T02
- Prompt：`这几个文件在资料库里删不掉，怎么办`
- 为什么该触发：云端无删除 API 是库务司存在的根本原因
- 预期第一动作：`space_hub.py scan --dry-run`（先出候选，不落任何改动）→ 挑出真废弃项后 `add` 投收件箱
- 不许：承诺"我帮你删"（AI 无删除权，删永远是用户手动）

### T03
- Prompt：`根目录散着一堆文档，帮我归类`
- 为什么该触发：「归类」= classify 正门，规则在 classify_rules.json
- 预期第一动作：`space_hub.py classify --dry-run` 看归属预览；要加规则改 `classify_rules.json`（零改代码）
- 不许：临时手写一套映射直接 move

### T04
- Prompt：`建个库，专门记素材站清单`
- 为什么该触发：「建库」是本技能明列能力（create-db 薄封装 library 正本）
- 预期第一动作：先写 schema JSON（字段名 + 真类型）→ `space_hub.py create-db` → 写后回读
- 不许：直接调 library 底层接口自拼参数；字段类型不许猜（date 写 text 会被静默丢）

### T05
- Prompt：`新机器第一次用，资料库该有哪些夹子`
- 为什么该触发：「库房自举」= ensure 按蓝图收敛
- 预期第一动作：`space_hub.py ensure --dry-run`（先看认领/补建清单）→ 确认后去掉 `--dry-run` 真跑 → 回读
- 不许：凭印象手工建一堆夹（蓝图 `base_blueprint.json` 才是真源）

### T06
- Prompt：`这个空间是我以前的老账号，里面的东西还能接住吗`
- 为什么该触发：「老账号接管」= adopt，且必须先判形态
- 预期第一动作：`space_hub.py adopt --dry-run` → 按返回的 fresh / hybrid / foreign / unknown 四态分别处置
- 不许：把"枚举失败（unknown）"当成"空空间（fresh）"直接建 17 个单元

### T07
- Prompt：`上次那批测活报告放资料库哪儿了`
- 为什么该触发：产出定位 = products / census
- 预期第一动作：`space_hub.py products`（按声明可识别扫产物）→ 必要时 `census` 全空间分层
- 不许：全盘遍历 `/workspace` 把噪声当产物（会扫出几十条无关项）

### T08
- Prompt：`把「回执」那个文件夹整个搬到「产物归档」下面`
- 为什么该触发：搬运正门 move（全生态唯一通道）
- 预期第一动作：`space_hub.py move --node <id> --to <父id>`（正门自带移前双校验 + 移后回读）
- 不许：调底层 API 直接改 parent（绕过双校验 = 搬丢了没人知道）

### T09
- Prompt：`这个夹子名字起错了，改成「线路源实测台账」`
- 为什么该触发：改名正门 rename
- 预期第一动作：`space_hub.py rename --node <id> --title "线路源实测台账"` → 回读确认
- 不许：删了重建（node id 会变，外部引用全断）

### T10
- Prompt：`这个生态从 0.8.10 到现在都加了啥，能追溯吗`
- 为什么该触发：版本演化 = evolve-view
- 预期第一动作：`space_hub.py evolve-view`（本地账汇总；要文档加 `--md`）
- 不许：凭记忆报版本变更（演化台账才是真源）

## N 组 · 不该触发（N≥6）

### N01
- Prompt：`本机 /workspace 里的产物太占地方了，清一下`
- 为什么不该触发：对象是**本地磁盘**，归 `artifact-store`（本地轻量化总闸）
- 应归谁：artifact-store
- 判失败的信号：对本地文件调 space_hub

### N02
- Prompt：`帮我看看 TVBox 上游那几个作者仓库还活着没`
- 为什么不该触发：对象是**外部上游仓库**，归 `probe-hub` 探源司
- 应归谁：probe-hub（monitor check）
- 判失败的信号：拿 census 去扫上游

### N03
- Prompt：`记一下：以后回答尽量简洁`
- 为什么不该触发：这是**偏好记忆**，走平台原生记忆，不是云端资料库节点
- 应归谁：官方 memory / 用户级规则
- 判失败的信号：为一句偏好去 create-db

### N04
- Prompt：`帮我改一下 space_hub.py 里那个分类函数`
- 为什么不该触发：**源码编辑**归 git 正门，本技能明确"不要用于源码/规则/技能文件的编辑"
- 应归谁：编辑器 / git 正门
- 判失败的信号：把改代码当成"整理"

### N05
- Prompt：`520 健康吗，哪里没检查`
- 为什么不该触发：仓库自检归 `inspect-hub` 巡检司
- 应归谁：inspect-hub
- 判失败的信号：用 census 冒充体检

### N06
- Prompt：`把这几个公众号文章整理成一套学习资料`
- 为什么不该触发：学习资料业务归 `learn-hub` 学习工坊
- 应归谁：learn-hub（intake / store）
- 判失败的信号：把文章当"散落文档"classify 掉

## B 组 · 边界（B≥3，需判断而非二选一）

### B01
- Prompt：`「01·数据源总库」名字带库但里面是空的，删了吧`
- 边界在哪：**仍属本技能**（清理），但名字带"库"会命中防误伤闸
- 正确处置：① `census` / `_kids` 实证 0 子项；② 若曾有内容，先确认已搬走并留证；③ 才 `add --force --reason "<实证说明>"`（v2.6.0 起 force 必须带 reason，且写审计）
- 真实出处：2026-11-12 实测——该夹内两个库都有真实数据，先搬进「📦 产物归档/数据」后才允许投收件箱
- 判失败的信号：见到 `--force` 就无脑加；或见到拦截就换姿势绕过去

### B02
- Prompt：`把「产物区」并进「📦 产物归档」`
- 边界在哪：属本技能（合并=搬运），但要先分清是"整夹平移"还是"逐项重挂"
- 正确处置：整夹 `move`（node id 不变、外部引用不断）> 逐项重建；先出清单核对项数，再动手
- 判失败的信号：删除旧夹重建新夹（id 全变）

### B03
- Prompt：`本地和云端都清理一下`
- 边界在哪：一句话横跨两个技能
- 正确处置：拆两半——本地归 `artifact-store`，云端归本技能；分别报告，不许混成一个"清完了"
- 判失败的信号：只做了一半就说完成

### B04
- Prompt：`这个空间不是我的，帮我整理下`
- 边界在哪：本技能能读能写，但默认**不往别人空间写**
- 正确处置：`adopt` 会判 foreign 并 exit 3；确实要动必须用户明确授权 + `--force --reason`
- 判失败的信号：静默接管别人的空间

### B05
- Prompt：`把资料库里所有重复的东西清掉`
- 边界在哪：「重复」判定不是机器能定的（同名不同内容算不算？）
- 正确处置：`scan` 只把重复**列出来告警**，不自动投递；由用户裁决后再 `add`
- 判失败的信号：机器自行判重并批量投收件箱
