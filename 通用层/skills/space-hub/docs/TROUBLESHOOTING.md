# space-hub · 故障排查（按症状查）

> **怎么用**：先找你的症状 → 看「先查什么」（可复制命令）→ 看「别做什么」。
> 机检：`verify/tests/test_troubleshoot.py` 要求 ≥5 条真实条目，占位符会被判红。

## 1. 任何命令都报「空间解析失败 / 未登记空间」

- **先查**：`python3 space_hub.py init --list` 能不能列出空间；当前账号是不是换了。
- **怎么办**：`init --space-id <ID>` 或 `init --title "<标题>"` 重新登记。换账号后**第一条命令必须是 init**。
- **别做**：不要猜 id、不要跳过 init 直接 add——四层解析全失败时会显式报错并列出可用空间，那是让你选，不是让你试。

## 2. add 被拒：「非空容器不得进待删收件箱」

- **先查**：这个夹真的有内容吗？`census --json` 看子节点数；还是"正在写入所以此刻是空的"。
- **怎么办**：先确认内容归属；确认整夹该删 → `add --node <ID> --force --reason "<为什么整夹该删>"`。
- **别做**：不要看到拒收就换写法再投一次（B-10）；收件箱会被用户整批删，非空容器进去就可能连根没了。

## 3. add 被拒：「空夹但名字像备份/库」

- **先查**：它只是位置不对，还是真废弃？`classify --dry-run` 能看出该归哪。
- **怎么办**：位置不对 → `classify --yes`（只移动、不删）；真废弃 → `add --force --reason "..."`。
- **别做**：不要把"空"当"该删"。空夹可能是刚建好还没写入，或内容在别处。

## 4. 命令跑完说成功，但云端看不到 / 位置没变

- **先查**：`move`/`rename` 的回读结果。本技能移后必回读，回读不符会返回 3 并说"不当作成功"。
- **怎么办**：等 1–2 分钟用 `census --json` 复核（常见是索引延迟）；仍不符按"未落地"处理，重跑一次。
- **别做**：不要因为退出码是 0 就当落地了——`add` 的 0 才是真移动，移动失败会返回 3 并保留清单行。

## 5. state 文件损坏（`space_hub_state.json` 解析失败）

- **先查**：`ls -lt <技能>/scripts/snapshots/ | head` 看最近快照；每次写前都会拍一张。
- **怎么办**：把最近一份 `*_state.json` 复制回 `space_hub_state.json`（或按需挑更早的），再跑 `inbox` 验证。
- **别做**：不要把损坏的 state 当"空收件箱"继续跑——那会让已投递记录全部丢失、重复投递（脚本本身会拒绝，别绕过它）。

## 6. `--force` 被拒：「必须配 --reason」

- **先查**：你是不是在绕护栏？绕的是哪一条（非空 / 像库 / 空间不匹配）。
- **怎么办**：写清"为什么该绕"再跑，例如 `--force --reason "已确认内容搬空，整夹废弃（2026-11-12 核对）"`。
- **别做**：不要为了"跑通"随便填一个 reason——它会被写进 state 审计，后人按这条记录判断当时是否想清楚。

## 7. 401 / 授权失效 / 一直提示未授权

- **先查**：换一个只读命令（`census`）是否也 401；是的话是账号层问题，不是空间解析问题。
- **怎么办**：重新登录授权后重跑 `init --list`；`adopt` 判形态时若枚举失败会报 `unknown`，**不要当 fresh 去建库**。
- **别做**：不要在 unknown 状态下跑 `ensure`——一次会建 17 个单元然后全失败。
