# skill-evolution 触发样本集（经验固化）

> **用途**：触发回归。判三件事——该触发时**有没有触发**、不该触发时**有没有乱触发**、触发后**第一动作对不对**。
> **本技能的特点**：管"经验→技能/规则"的转化，**不管业务内容本身**；且必须"先查重、再提案、用户点头才落地"。
> **判据真源**：`SKILL.md`（能力 ①-⑤、阈值"复发≥3 次"、负边界）。本文件只放样本。
> **登记**：`verify/skill_contracts.json` → `trigger_samples`；C6 机检分组数量。

## T 组 · 应触发（T≥8）

### T01
- Prompt：`这毛病第三次犯了吧，能不能根治`
- 为什么该触发：复发≥3 次正是立项阈值
- 预期第一动作：先采复发信号（会话台账 / CHANGELOG / 资料库经验层），确认"同一问题真出现了 3 次"再谈立项
- 不许：凭一句"好像犯过几次"就动手建技能

### T02
- Prompt：`要不要把这事做成一个技能`
- 为什么该触发：技能立项咨询
- 预期第一动作：**先去重比对**——现存技能/脚本里有没有等价实现；没有才出提案
- 不许：直接开写 SKILL.md

### T03
- Prompt：`这些规则重复了，收敛一下`
- 为什么该触发：规则去重与复盘是明确能力
- 预期第一动作：列重复条款（文件 + 行号）→ 定真源 → 其他地方改成指针（M1/M2）
- 不许：就地删掉一处了事

### T04
- Prompt：`这次的坑记下来，别再犯`
- 为什么该触发：经验沉淀
- 预期第一动作：先判归属（进规则？进技能 references？进 SOP？）→ 再写入唯一真源
- 不许：到处抄一份（那是重复源头）

### T05
- Prompt：`这个问题反复出现，我想彻底解决`
- 为什么该触发：复发问题根治
- 预期第一动作：先判"孤例还是模式"（M6）→ 模式才做机制级修复
- 不许：只修这一次的现场

### T06
- Prompt：`这个技能该升级了，内容过时了`
- 为什么该触发：技能升级
- 预期第一动作：读现有 SKILL.md + CHANGELOG → 定位过时段 → 改 + 升版本 + 记 CHANGELOG（三件套）
- 不许：改了不升版本（下次无法对账）

### T07
- Prompt：`复盘一下这个月都踩了什么坑`
- 为什么该触发：周期性复盘
- 预期第一动作：汇总（CHANGELOG / 回执 / 收件箱 / 巡检 findings）→ 分类"已修 / 待修 / 该立规则"
- 不许：只列不判

### T08
- Prompt：`把它写进规则，以后都按这个来`
- 为什么该触发：规则固化
- 预期第一动作：先查是否已有等价条款（真源在哪）→ 有则改真源；无则新增并给编号（不占用已用编号）
- 不许：新建一份"补充规则"平行文件（多真源）

### T09
- Prompt：`这个技能好像跟另一个功能重复`
- 为什么该触发：去重比对
- 预期第一动作：比对两者触发词/能力/正门，输出"重叠点 + 差异点 + 建议（合并/划界/保留）"
- 不许：直接删一个

## N 组 · 不该触发（N≥6）

### N01
- Prompt：`帮我把这件事办了`
- 为什么不该触发：一次性任务，负边界明写"不用于一次性操作的经验固化"
- 应归谁：对应业务技能
- 判失败的信号：为一次任务建技能

### N02
- Prompt：`帮我做份 PPT`
- 为什么不该触发：业务内容加工不归本技能
- 应归谁：PPT 技能
- 判失败的信号：—

### N03
- Prompt：`把这批文章整理成学习资料`
- 为什么不该触发：归 `learn-hub`
- 应归谁：learn-hub

### N04
- Prompt：`520 体检`
- 为什么不该触发：归 `inspect-hub`
- 应归谁：inspect-hub

### N05
- Prompt：`这个 bug 帮我修了`
- 为什么不该触发：直接修即可（除非它已复发≥3 次要根治）
- 应归谁：直接改代码；复发才回来找本技能
- 判失败的信号：为单次 bug 立项

### N06
- Prompt：`建个资料库`
- 为什么不该触发：归 `space-hub`
- 应归谁：space-hub

### N07
- Prompt：`把这条记忆改一下`
- 为什么不该触发：记忆增删归平台原生
- 应归谁：官方 memory

## B 组 · 边界（B≥3）

### B01
- Prompt：`别问了，直接把这个新技能落地`
- 边界在哪：负边界明写"提案→确认→落地"，不许擅自落地
- 正确处置：给一页提案（解决什么/触发条件/边界/与现有技能关系），用户点头再写
- 判失败的信号：不问就建

### B02
- Prompt：`就犯了两次，也算复发吧`
- 边界在哪：阈值是 ≥3 次（判据在 SKILL.md）
- 正确处置：说明阈值；两次可先记进观察清单（不立项）
- 判失败的信号：降阈值凑立项

### B03
- Prompt：`这功能跟现有技能有点像，但也想单独做一个`
- 边界在哪：重叠 ≠ 必须合并，但要先划界
- 正确处置：先做去重比对，给出"合并 / 划界 / 独立"三选一的建议与代价，由用户定
- 判失败的信号：不比对直接建

### B04
- Prompt：`把这条经验同时写进三个技能里`
- 边界在哪：违反 M1 单一真源
- 正确处置：写进唯一真源，其他两处只留指针（文件+小节）
- 判失败的信号：三处各抄一份全文
