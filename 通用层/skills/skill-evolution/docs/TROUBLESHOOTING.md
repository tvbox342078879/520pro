# skill-evolution · 故障排查（按症状查）

> **怎么用**：自我进化的坑都在"**经验写重复了 / 技能建了但不合格**"。
> 机检：`verify/tests/test_troubleshoot.py` 要求 ≥5 条真实条目。

## 1. 契约机检红：版本不一致（C4）

- **先查**：`python3 verify/skill_contract_check.py` 的报错会列出四个来源（contracts / SKILL / CHANGELOG / MANIFEST）。
- **怎么办**：四处改成同一个号：`SKILL.md` frontmatter、`CHANGELOG.md` 首条、`MANIFEST.json` 登记、`verify/skill_contracts.json`。
- **别做**：不要只改 SKILL 的 version 就算完——另外三处会在下一次机检翻红。

## 2. 契约机检红：镜像 sha 不一致（C5）

- **先查**：是不是改了仓库里的文件但没重装。
- **怎么办**：`bash install.sh --user-skill`（按原 SCOPE）重装，再跑 `--require-mirror` 复核。
- **别做**：不要手工 cp 单个文件了事——漏一个就是下一次红；确实只改一个文件时，改完立刻跑契约机检。

## 3. 同一个坑被写成三条不同措辞的经验

- **先查**：入库前的三问做了没有（能更新吗 / 是 NOOP 吗 / 才新增）。
- **怎么办**：合并成一条，其他两条留指针；新增条目里写"最接近的既有条目 + 差在哪"。
- **别做**：不要"多写一条更保险"——重复条目会让后人不确定该信哪条。

## 4. 新技能建出来了，但路由不触发

- **先查**：`description` 五组齐不齐（触发 / 能力枚举 / 正门锚点 / 自省锚点 / **负边界**）；目录名与 frontmatter `name` 是否一致。
- **怎么办**：补齐五组；负边界必须写"不要用于 …"；跑契约机检 C2。
- **别做**：不要靠堆触发词解决——堆词只会增加误触发（D 工程的反例样本就是治这个）。

## 5. 脚手架生成的技能"看起来完整"，实际缺项

- **先查**：生成结果里有没有 `degrade_reasons`；缺哪些字段。
- **怎么办**：按 reasons 逐项补齐（version / CHANGELOG / 边界 / 锚点）。
- **别做**：不要因为"文件都在"就当合格——空壳技能会被 C1/C2 当场判红。

## 6. 经验记了但没人用 / 下次又犯

- **先查**：这条经验落在哪：技能 SKILL？规则？还是只在会话里说过。
- **怎么办**：能变成判据的进规则/机检；只能靠人记的写进 TROUBLESHOOTING 的症状表。
- **别做**：不要只写进 CHANGELOG——那是历史档案，没人会翻。
