# 技能自我进化引擎（skill-evolution）

> **第一动作（自省锚点）**：命中触发词后**先读本技能全文**再动手；不许看见触发词/脚本就直接执行——
> 判据在本文件，不在记忆里；跳过本文件动手，等于没有判据。

> 通用铁律由 `core-8.md` + 薄壳 + `zh-style.md` 三通道全局强制，本技能直接继承、不重复声明（见 SOP 20.9 / M2）。

## 何时使用
- 触发词（唯一真源）：沉淀经验 / 做成技能 / 反复犯 / 复盘 / 规则整理 / 自我进化 / 根治 / 老犯
- 同一类问题第 2 次出现 → 记入经验库，标记"易复发"。
- 同一类问题第 3 次出现 → 立项生成独立、可升级的技能。

## 职责与边界
- 只固化**通用或可升级**的经验；一次性操作不生成技能。
- 生成的技能写入 `.codebuddy/skills/<name>/`（官方自动加载路径），并进 git 永久历史。
- **提案 → 用户确认 → 落地**：可自动立项与生成提案，不擅自落地未经确认的新技能。
- 不绑定任何业务领域；是 SOP 第 17 章"经验复用"的自动化发动机。

## 工作流
1. 采集复发信号：扫描会话台账、CHANGELOG、资料库经验层。
2. 去重：比对既有技能与规则，确认无等价实现（复用 `equiv_check` 思路）。
   **执行化 = 经验入库三问（v1.1.0，先问再写）**：
   - ① **能更新吗**：同一问题已有条目 → 追加证据 / 修判据 / 补边界，**不新建**；
   - ② **是 NOOP 吗**：已有等价条目且本次无新证据 → **不写**，只回一个指针（文件 + §小节或条目号）；
   - ③ 前两问都否才**新增**，且新条目必须写明「最接近的既有条目 + 差在哪」，防同义条目繁殖。
   > 为什么：只做"新增"时，同一个坑会被不同措辞写五遍，后人不确定该信哪条；更新与 NOOP 也是合法结果。
3. 立项：复发 ≥3 次 → 生成提案，写明"解决什么 / 触发条件 / 边界"。
4. 待用户确认后，脚手架生成 `SKILL.md`（frontmatter + 占位正文）。**降级必须报因**：缺哪些字段
   （如 description 五组的"负边界"、version、CHANGELOG 三件套）要逐项列成 `degrade_reasons: [...]`
   输出，**不许**静默产出一个看起来完整、实则缺项的空壳。
5. 回写 CHANGELOG 与 `MANIFEST.json`，提交 git。
6. 新技能的一句话短名对齐 `docs/registry.md` 第七节 `canonical_short`（C1）；收尾跑 `verify/terminology_check.py`（C5）。

## SOP 对齐
- 第 17 章：Auto Memory + Typed Memory（user/feedback/project/reference）的自动化版——复发经验落技能而非仅存记忆。
- 第 18 章：生态自我生长机制。第 16 章：产物进 git 永久历史，不靠本地检查点。
- 20.12：技能契约由机检第 7 项守护，规范化整改不再悄悄退化。
