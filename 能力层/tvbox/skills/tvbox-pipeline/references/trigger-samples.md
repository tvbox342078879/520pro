# tvbox-pipeline 触发样本集（出品流水线）

> **用途**：触发回归。判三件事——该触发时**有没有触发**、不该触发时**有没有乱触发**、触发后**第一动作对不对**。
> **为什么要写清反例**：本技能与 `probe-hub` 最容易混——一句话之差，"找源"该去探源司、"加工已有源"才来这里。
> **判据真源**：`SKILL.md`（两入口分流表、铁律顺序）+ `SOP_整包加工.md`（A 入口必读）。本文件只放样本。
> **登记**：`verify/skill_contracts.json` → `trigger_samples`；C6 机检分组数量。

## T 组 · 应触发（T≥8）

### T01
- Prompt：`这个接口做个 json`
- 为什么该触发：A 入口最典型表达（手上有在线接口地址）
- 预期第一动作：**体系识别**（判 jar系/直链系/内置系 → 定成品名 `<体系><日期>_<站数>站`），并按 `SOP_整包加工.md` 走
- 不许：上来就抓取/拼接（跳步即违规）

### T02
- Prompt：`这个配置能不能用`
- 为什么该触发：已有源的可用性判定 = 本技能（测活）
- 预期第一动作：跑测活（A 入口第 4 步，或 B 入口 `check_live.py`），给出存活/失效数与死因
- 不许：只看 json 结构完整就判"能用"

### T03
- Prompt：`更新一下 TVBox 配置`
- 为什么该触发：B 入口（配置同步三脚本）
- 预期第一动作：`python3 "$SCRIPT_DIR/collect_repos.py"` → `check_live.py sources.json` → `merge_config.py`
- 不许：手工逐条 curl、手工改 JSON

### T04
- Prompt：`这个本地包帮我拆一下`
- 为什么该触发：A 入口拆分（四类站点线拆法）
- 预期第一动作：体系识别 → 按 SOP 拆（采集/直链分开归档、相对地址转绝对）
- 不许：一股脑塞进一个 json

### T05
- Prompt：`这个地址还能用吗`
- 为什么该触发：单条可用性 = 测活
- 预期第一动作：测活该地址，输出"活/死/无法判定"三态之一 + 依据
- 不许：把 timeout 写成"死"

### T06
- Prompt：`直播源整理一下`
- 为什么该触发：lives 属本技能处理对象
- 预期第一动作：体系识别（lives 单独归置）→ 全量测活 → 纯可用版
- 不许：和点播源混在一个文件里

### T07
- Prompt：`jar 系的包怎么弄`
- 为什么该触发：体系识别四类之一
- 预期第一动作：读 `docs/manual_2_5_2_识别流程.md` + `manual_2_5_4_新体系自动建系.md`，按体系走
- 不许：按直链系的做法硬套

### T08
- Prompt：`把存活源并进主配置`
- 为什么该触发：B 入口第 3 步（过滤失效源 → master_config.new.json）
- 预期第一动作：`merge_config.py` → **产出新文件** `master_config.new.json`，报"存活 N / 失效 M"
- 不许：直接覆盖线上主配置（要先出新文件核对）

### T09
- Prompt：`这个包做完了入个库`
- 为什么该触发：A 入口最后一步（入库登记）
- 预期第一动作：按 SOP 的入库登记表登记（成品名/站数/测活结果/日期）→ 需要放云端再走 `space-hub archive_out`
- 不许：只把文件丢在某目录就说"入库了"

## N 组 · 不该触发（N≥6）

### N01
- Prompt：`帮我找几条新线路`
- 为什么不该触发：**手上没有源** → 先走探源司（本技能只管已有源的加工）
- 应归谁：`probe-hub`（search / harvest）
- 判失败的信号：拿 pipeline 去搜源

### N02
- Prompt：`作者仓库还活着吗`
- 为什么不该触发：上游监测归探源司
- 应归谁：probe-hub（monitor check）
- 判失败的信号：用测活冒充仓库监测

### N03
- Prompt：`这个源为什么死了，帮我修`
- 为什么不该触发：修源（死因七型 → 五路由）归探源司 repair
- 应归谁：probe-hub（repair/engine.py）
- 判失败的信号：在 pipeline 里改源代码

### N04
- Prompt：`写个 py 源`
- 为什么不该触发：写源 forge / 四门禁归探源司
- 应归谁：probe-hub（forge verify / gate）
- 判失败的信号：pipeline 里手写源

### N05
- Prompt：`资料库整理一下`
- 为什么不该触发：云端空间治理归 `space-hub`
- 应归谁：space-hub
- 判失败的信号：—

### N06
- Prompt：`把这些文章做成学习资料`
- 为什么不该触发：学习资料归 `learn-hub`
- 应归谁：learn-hub

### N07
- Prompt：`520 体检`
- 为什么不该触发：仓库自检归 `inspect-hub`
- 应归谁：inspect-hub

## B 组 · 边界（B≥3）

### B01
- Prompt：`手上暂时没源，你先给我做个能用的包`
- 边界在哪：**缺源请先走 probe-hub**（SKILL.md 边界明写）
- 正确处置：先说明"本技能只管已有源的加工"，问用户要不要先让探源司采一批；不擅自编源
- 判失败的信号：凭空生成一堆假源充数

### B02
- Prompt：`测活都过了，直接入库吧`
- 边界在哪：测活过 ≠ 可入库（还要去重、体积、体系识别、成品命名、登记）
- 正确处置：按铁律顺序走完六步再登记
- 判失败的信号：跳过去重/体积直接登记

### B03
- Prompt：`直接改线上主配置，别整新文件了`
- 边界在哪：覆盖线上不可逆
- 正确处置：坚持先出 `master_config.new.json`，报差异（新增/删除/失效各多少），用户点头再替换
- 判失败的信号：无备份直接覆盖

### B04
- Prompt：`这个接口是 py 线，你能直接跑吗`
- 边界在哪：py 源能不能跑属写源/测活范畴（探源司），本技能只管"加工出品"
- 正确处置：交探源司 `livecheck --spider` 验；本技能按验过的结果加工
- 判失败的信号：自己写个 runner 跑 py 当验证
