# tvbox-pipeline · 故障排查（按症状查）

> **怎么用**：先找症状 → 看「先查什么」→ 看「别做什么」。整包坊的坑集中在**"加工完了但结果是空的/重的/断的"**。
> 机检：`verify/tests/test_troubleshoot.py` 要求 ≥5 条真实条目。

## 1. 加工跑完，分类是空的 / 类目全挤在一个默认项

- **先查**：`docs/manual_3_1_分类参数写死.md`——分类参数写在哪、当前值是什么。
- **怎么办**：按正本改参数（不是改脚本）；改完重跑一次，回读分类结果确认不是"写成功但没生效"。
- **别做**：不要在输出 json 里手改分类糊过去——下次加工又被覆盖。

## 2. 播放地址是相对路径，播放器打不开

- **先查**：抽一条地址看是不是 `/vod/xxx.m3u8` 这种以 `/` 开头的相对形态。
- **怎么办**：走 `docs/manual_4_2c_相对地址转绝对.md` 的正则/拼接规则，转完真拉一条确认可播。
- **别做**：不要拿站点首页去拼——基址要从接口返回的 host 或配置里的 site url 取。

## 3. 去重后少了源，怀疑被误删

- **先查**：`docs/manual_4_5_全量去重.md` 的去重键（是 url？还是 name+url？）；先跑 `--dry` 看去重前后对照。
- **怎么办**：按"保留最早/保留可用"的策略明确取舍；被合并的要有记录可追。
- **别做**：不要用"标题相同"当唯一键——同名不同源很常见，会真删掉可用线路。

## 4. 加工完提源入总库失败 / 总库里看不到

- **先查**：`docs/manual_6_4_提源入总库.md` 的入口命令与目标库 id；先跑只读查询确认库在。
- **怎么办**：按 SOP 走 promote 正门；失败要看返回的 error 与 reason（不要只看"成功"两字）。
- **别做**：不要直接往库里手写记录——记录格式（字段/枚举）与写入通道都在正本里。

## 5. 遇到没见过的体系，不知道塞哪

- **先查**：`docs/manual_2_5_4_新体系自动建系.md` 的判据（什么情况才算"新体系"）。
- **怎么办**：确认是新体系 → 按自动建系流程；只是命名不同 → 走 `manual_2_5_2_识别流程.md` 归到既有类目。
- **别做**：不要为每个新站建一个类目——类目膨胀比漏归更难收拾。

## 6. 文档里写的 pipeline 脚本路径跑不起来

- **先查**：真实位置在 `tvbox-core/scripts/pipeline.py`（本技能与 tvbox-core 共用引擎）。
- **怎么办**：用 `tvbox pipeline ...` 正门，或按真实路径跑。
- **别做**：不要在 pipeline 里再复制一份引擎——两份必然漂移。
