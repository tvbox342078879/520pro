# tvbox-core · 故障排查（按症状查）

> **怎么用**：tvbox-core 是**共享库**（无 SKILL.md，不被路由），它挂了所有 TVBox 技能一起挂。
> 机检：`verify/tests/test_troubleshoot.py` 要求 ≥5 条真实条目。

## 1. `import core` 失败 / ModuleNotFoundError

- **先查**：`ls scripts/core.py`；技能目录里有没有多出一份 `SKILL.md`（有就是装错层级）。
- **怎么办**：按用户级重装（`bash install.sh --user-skill`）；确认 `~/.codebuddy/skills/tvbox-core/scripts/core.py` 在位。
- **别做**：不要在 probe-hub/pipeline 里各放一份 core.py —— 两份必然漂移，且哪份生效说不清。

## 2. 某个源被拉黑了，但其实是好源

- **先查**：黑名单主键是什么（url 归一后？域名？）；命中是精确匹配还是子串匹配。
- **怎么办**：按"黑名单主键与三层分级"正本复核；误杀就走复核移出，并记下误杀原因。
- **别做**：不要用子串匹配判黑——`ad.`/`gg.` 这类会误伤正常路径（S225 已把广告判定换成域名黑名单）。

## 3. 不确定该不该拉黑 / 该拉黑到哪一级

- **先查**：三层分级（hot/warm/cold）与 `enforce_level` 的对应关系；这条源的死因分型。
- **怎么办**：先判死因，再定级；"无法判定"的不要拉黑，挂待复测。
- **别做**：不要因为"怕它坏"就提前拉黑——黑名单越大，误杀面越大。

## 4. 羊壳环境没有 pycryptodome，源一 import 就崩

- **先查**：报错栈是不是 `Crypto` 导入失败。
- **怎么办**：用 `_aes_fallback.py`（probe-hub 提供的纯 Python 兜底）；跑一次 NIST 向量自检。
- **别做**：不要把密钥硬编码进源——AES 兜底解决的是"库缺失"，不是"凭据管理"。

## 5. 规则册里 tier 与 enforce_level 对不上

- **先查**：该条规则的 `tier` 与 `enforce_level` 组合是否在允许表内（hot↔GATE 等）。
- **怎么办**：按一一对应表改正；改完跑规则闸门（R221/R222）。
- **别做**：不要为了"让它生效"硬改 enforce_level——分层与闸门是配套的。

## 6. 规则明明写了，实际没生效

- **先查**：判据是否落在**执行路径**上（规则写在文档里不等于代码会读它）。
- **怎么办**：看对应闸门脚本有没有读这条；没有就补"读+判+报"三步。
- **别做**：不要用"文档里写了"当"已生效"——见 §3.13 静默缺陷七例。
