# probe-hub · 故障排查（按症状查）

> **怎么用**：先找症状 → 看「先查什么」→ 看「别做什么」。探源司的坑大多是**把"没测出来"当成"测出死了"**。
> 机检：`verify/tests/test_troubleshoot.py` 要求 ≥5 条真实条目。

## 1. 一整批探活全是「失败 / 无法判定」

- **先查**：单条真跑一次 `livecheck <url>`，看是"这一条不行"还是"全都超时"。全超时先怀疑环境（沙箱网络/代理）。
- **怎么办**：单条能过 → 批量参数问题（并发/超时/字段名）；单条也全超时 → 记「无法判定」，换环境复测，别写"源全死了"。
- **别做**：不要拿"批量结果"直接下结论——批量失败与源失效长得一模一样，先分层。

## 2. 批量里一堆条目「无地址字段」被判失败

- **先查**：输入 json 的键名。本司全线用 `api接口`，而 livecheck 兼容 `api接口/api/url/link/地址`。
- **怎么办**：确认输入文件里到底叫什么键；缺地址就补，或在生成端统一成 `api接口`。
- **别做**：不要把它当"源失效"清理掉——那是**配置读丢了**，不是源死了（S144 踩过，全部拿空 URL 去测，报了一片失败）。

## 3. 站点返回 404，是不是就该拉黑？

- **先查**：404 的形态：真不存在、还是风控/改名/私库（换 UA、换路径、看同站其他接口）。
- **怎么办**：至少两种取证后再判；判死要走 `repair` 的死因分型，不是直接 `remove` 监测目标。
- **别做**：不要一次 404 就删目标——404 ≠ 死（三态：这是"无法判定"的典型）。

## 4. 接口 200、返回体也不空，但播放器打不开

- **先查**：真拉一次播放地址：点播看是否拿到 `vod_play_url` 并能拉首片；直播看 m3u8 分片是否 >0 字节。
- **怎么办**：200 但拉不动 → 按 §3.15 用 `livecheck --kind parse`（或 `--video/--wait`）真跑；仍 0 流就是内容层死。
- **别做**：不要用 HTTP 码当通过判据——本司判据是"真出流"，不是"服务器理我了"。

## 5. `ModuleNotFoundError: core` / 探源司整体起不来

- **先查**：`ls ~/.codebuddy/skills/tvbox-core/scripts/core.py`。
- **怎么办**：装 tvbox-core（`bash install.sh --user-skill` 会一起装）；确认它**没有** SKILL.md（有就是装错层级）。
- **别做**：不要在 probe-hub 里复制一份 core.py —— 两份必然漂移。

## 6. 源里有 AES，羊壳没装 pycryptodome，整源 import 就挂

- **先查**：报错栈是不是 `Crypto` / `Cryptodome` 导入失败。
- **怎么办**：用 `scripts/_aes_fallback.py`（模块形态 `from _aes_fallback import decrypt_bytes`，或命令行 `--decrypt`）；改完跑 `--crosscheck` 与 forgekit 内联片段对账。
- **别做**：不要只改一处——模块与内联片段是两份实现，改一份漏一份（S224 定案）。

## 7. `monitor status` 报 0 个目标 / 监测台空的

- **先查**：是不是新机器？运行时册（monitor_targets 等）按设计**不随分发**，首跑才自建空册。
- **怎么办**：确认安装器剥离逻辑生效（空机 0 目标是对的）；要恢复监测就在新机重新加目标。
- **别做**：不要把"空册"当"监测全挂"——那是防私产泄露的正常形态。
