# probe-hub 触发样本集（探源司）

> **用途**：触发回归。判三件事——该触发时**有没有触发**、不该触发时**有没有乱触发**、触发后**第一动作对不对**。
> **为什么这个技能尤其需要反例**：本技能的多数动作是**重操作**（真拉线路、扫仓库、改成品源库），误触发的代价是打空转、误判死源、甚至写坏 DB_PROD。
> **判据真源**：`SKILL.md`（§2.1 硬约束、§3.5/§3.7 判据、§3.12 写源）。本文件只放样本。
> **登记**：`verify/skill_contracts.json` → `trigger_samples`；C6 机检分组数量。

## T 组 · 应触发（T≥8）

### T01
- Prompt：`这批线路帮我测一下活`
- 为什么该触发：真实测活是探源司核心（点播真拉 vod_play_url / 直播真拉分片）
- 预期第一动作：`python3 scripts/livecheck.py`（批量走 batch）→ 出通过率 + 死因分型；收尾自动 `archive_out` 归档到「🔍 探源产出」
- 不许：只 curl 一下 HTTP 200 就判活（那是没测）

### T02
- Prompt：`作者仓库还活着吗，有没有更新`
- 为什么该触发：「监测」面：存活/内容变更/新增文件/活跃度
- 预期第一动作：`probe.py monitor check`（必要时 `diff` 看变更、`forecast` 看活跃度）
- 不许：直接 git clone 看（不写 DB_UPSTREAM = 结论没落账）

### T03
- Prompt：`帮我找几个新的有效仓库`
- 为什么该触发：「搜索扩库容」：多平台搜索 → rank → verify
- 预期第一动作：`probe.py search github`（或 gitee/gitlab）→ `rank` 打分 → `verify` 验活
- 不许：搜到就收（没过 verify 的目标不进监测名单）

### T04
- Prompt：`这个源坏了，帮我修一下`
- 为什么该触发：修源面（死因七型 → 五路由）
- 预期第一动作：`python3 scripts/livecheck.py` 先拿**死因分型** → `python3 repair/engine.py checkup <url>` 定路由（route/drafts/apply/repair 逐级）
- 不许：看到报错直接改代码（没定死因就改 = 猜）

### T05
- Prompt：`这个站点源的 py 写得对不对`
- 为什么该触发：写源 verify（过验才留档）
- 预期第一动作：`probe.py forge verify <源.py>`（要留档加 `--save`）；四门禁再走 `gate`
- 不许：没过验就说"写好了"

### T06
- Prompt：`这个壳源把直链抠出来`
- 为什么该触发：壳源侦察与抠链（S196）
- 预期第一动作：`probe.py shellcrack probe <url>`（批量 `scan`，缺候选册会自动建空册）
- 不许：手工猜直链

### T07
- Prompt：`这个直播源里全是广告，清一下`
- 为什么该触发：HLS 广告净化（61 域名黑名单 + 三段判定）
- 预期第一动作：`probe.py hls_clean` → 报清理前后分片数与命中域
- 不许：无脑全删 ts 片段（会伤正片）

### T08
- Prompt：`GitHub 配额还剩多少`
- 为什么该触发：凭据与配额面
- 预期第一动作：`probe.py token` / `probe.py limits`
- 不许：凭记忆报"应该还有"

### T09
- Prompt：`这个源为啥死的，是域名挂了还是接口改道`
- 为什么该触发：死因分型是判据驱动的核心能力
- 预期第一动作：`livecheck` 拿分型（域名挂 → 判「无法判定」，不能判死）→ 再决定路由
- 不许：把"拉不到"一律判死（三态折叠）

### T10
- Prompt：`把这条死源从成品库里剔了`
- 为什么该触发：成品源库维护（prune）
- 预期第一动作：`probe.py harvest prune`（先 readback 确认死因证据）→ 报告剔了哪条、依据是什么
- 不许：没证据就剔

## N 组 · 不该触发（N≥6）

### N01
- Prompt：`这个接口帮我做成能用的 json 包`
- 为什么不该触发：**手上已有源、要加工出品**归 `tvbox-pipeline`（A 入口）
- 应归谁：tvbox-pipeline
- 判失败的信号：拿 harvest 去干整包加工

### N02
- Prompt：`把这些网盘资料整理成学习资料`
- 为什么不该触发：学习资料业务归 `learn-hub`（网盘取料 `pan` 已于 2026-11-12 迁过去）
- 应归谁：learn-hub
- 判失败的信号：用探源司的 pan 老路径

### N03
- Prompt：`资料库乱，帮我理一下`
- 为什么不该触发：云端空间治理归 `space-hub`
- 应归谁：space-hub
- 判失败的信号：用探源司去扫云端节点

### N04
- Prompt：`520 体检一下`
- 为什么不该触发：本生态自检归 `inspect-hub`（探源司盯外部，巡检司盯自家）
- 应归谁：inspect-hub
- 判失败的信号：混淆两个"检查"

### N05
- Prompt：`把这个视频转成 mp3`
- 为什么不该触发：与本域无关的通用任务
- 应归谁：通用工具/命令行
- 判失败的信号：因为"都是文件处理"就路由进来

### N06
- Prompt：`更新一下主配置的订阅`
- 为什么不该触发：配置同步归 `tvbox-pipeline`（B 入口）
- 应归谁：tvbox-pipeline
- 判失败的信号：把"更新订阅"当成采源

## B 组 · 边界（B≥3）

### B01
- Prompt：`这条源我本地能播，就别测了吧，直接标活`
- 边界在哪：**用户自测 ≠ 探源司测活**（探源司要真拉播放地址/分片，且要留证据）
- 正确处置：明说"未经本司测活不能标活"，可选：跑 livecheck 单条给出证据再标
- 判失败的信号：凭用户一句话写活

### B02
- Prompt：`作者仓库 404 了，是不是跑路了`
- 边界在哪：404 可能是临时风控/改名/私库，**不等于死**
- 正确处置：按三态——`monitor check` 拿状态 → 多次复验仍 404 才记「疑似停更」，结论写"无法判定/待复验"，不擅自除名
- 判失败的信号：一次 404 就 `remove` 监测目标

### B03
- Prompt：`把死源全清了`
- 边界在哪：「死」的判定门槛（几次失败、间隔多久）属于判据，不是用户一句话
- 正确处置：先给"被判死的清单 + 每条证据（死因/复验次数/时间）"，用户确认后再 prune
- 判失败的信号：批量直接剔

### B04
- Prompt：`这个源能播但内容不全，算好源吗`
- 边界在哪：能播 ≠ 好源（写源四门禁：能播放/稳定兜底/内容齐全/精简体积）
- 正确处置：走 `gate` 四项逐条判，输出"过几门、卡在哪门"
- 判失败的信号：能播就判"好"
