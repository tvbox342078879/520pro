## 一、死因分型（livecheck.death_cause，S221 落地）

业内核心论断：**自愈的核心不是 AI，而是失效分型**——403 ≠ 选择器失效 ≠ 证书过期 ≠ 结构改版，分型错了修复必然瞎打。

| 分型 | 判据（evidence 特征） | 修复路由 |
|---|---|---|
| 域名层 | 不可达/DNS/证书类证据 | 换域修复（host/self.host/拼接全覆盖，严禁臆造新接口，换后立即复验） |
| 接口层 | HTTP 4xx / 路径 404 | 接口改道（判路径/前缀变化，命中采集接口优先走"字段标准最稳"路） |
| 内容层 | 假活 / vod_play_url 空 / 播放地址拉不动 | 接口改道（接口活但内容断） |
| 语法层 | py/js 源码崩 | 小补 1 轮（硬约束：只修报错行；edits.old 必须原文逐字片段），超限升级重写 |
| 结构性 | XML 接口可达但无地址 | 整站重写（重新侦察→生成整份源码→真跑复验） |
| 未定·网络 | 无法判定（超时/抖动/证书） | 先复验，不算死（M-R60 三态） |

实现单一事实源：`scripts/livecheck.py::death_cause`；分型→路由映射：`REPAIR_ROUTE`。
`repair/engine.py` 只消费本函数输出，禁各自重写（M-R38/M-R71）。

## 二、写源硬性契约 r146/r147/r148（判据入库，验收对齐）

### r146 · 线路必播
第三方解析线路（量子/非凡/暴风…）**首集逐条真取**，拿不到直链就整条丢掉，最多留 3 条；全部取不到才留 1 条原样 + remarks 注明。
> 与 livecheck 现有验收的差异：livecheck 只验"有播放地址"，r146 要求"逐条线路真取得出直链"——探源司验收采纳此条（更狠）。

### r147 · 直链形态
`playerContent` 返回的 url 必须能拉到 `#EXTM3U` 或 `video/*`。
自查口诀：**host 是 CDN 域才对，站点主域的 .html 几乎一定是写错了，宁可 parse:1**。

### r148 · 三数字模板选集判据
形如 `sid-nid.html` 的三数字链接：**所有链接第三个数全同而第二个数不同 = sid/nid 顺序**——用分布特征判字段语义，比逐个试快得多。
