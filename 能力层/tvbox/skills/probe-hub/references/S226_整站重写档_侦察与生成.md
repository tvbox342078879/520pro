# S226 · 整站重写档（batch 4）：侦察 → 生成 → 真跑复验

> 上一轮 rewrite 策略只会返回 `not_applicable`（"batch 4 未实现"）。
> 本轮把它做出来了，核心结论先说：**rewrite 的难点不是"让模型写一份源"，是"敢不敢信它写的"**。

---

## 一、为什么 rewrite 必须先侦察

小补（patch）只需要知道「哪一行错了」；**整站重写要知道「这站怎么出数据」**。

不给侦察结果就让 LLM 重写，它必然套一个 maccms 模板 —— 这就是 r147 记下的坑：
`host` 写成站点主域的 `.html`，播放器一条都拉不到，跑起来是「接口通、零播放地址」。

所以 rewrite 的前置不是「写代码」，而是先回答三个问题：

| 问题 | 决定什么 |
|---|---|
| 数据从哪来（内联首屏 / XHR / 标准 CMS / 静态 HTML） | `homeContent`/`categoryContent` 怎么取 |
| 分页与筛选走哪套（路径尾页码 / query / 滚动） | URL 拼法 |
| 详情页 → 播放地址是直链还是需解析 | `playerContent` 的 `parse` 值 |

## 二、`repair/recon.py`：侦察档

```bash
python3 repair/recon.py <url> --depth 2        # 人读
python3 repair/recon.py <url> --depth 2 --json # 给程序
python3 repair/recon.py --selftest             # 离线自检（不联网）
```

产出：命中特征（每条都对应一个**生成决策**，不是大而全指纹库）、导航分类、分类页样例、
分页形态、详情页选集形态、接口线索、**无法判定项**。

### 侦察阶段踩到的三个坑（都是实测出来的）

#### 坑 1：跳转壳 ——「抓到了内容 ≠ 抓到了站点」

`mtosz.com` 首页返回 HTTP 200、5556 字节，内容是一个 `Redirecting...` 单页。
拿这份 HTML 做侦察，会得出「无特征、无分类、无列表」的**错误结论**。

> 这和 M-R57「没查到 ≠ 没有」是同一类错误，只是伪装成成功响应。

处理：识别 `meta refresh` / `location=` / `location.replace()`，跟跳（最多 2 跳防环）。

#### 坑 2：JS 挑战型防爬 —— cookie 值静态取不到

同站真实形态是 `document.cookie=`k=${btoa(resp)};max-age=5`` 后才放行。
值依赖接口返回，**静态取不到**。

处理分两种：
- cookie 是**字面量**（`document.cookie="abc=123;max-age=5"`）→ 提取出来带上重试
- cookie 是**模板串**（含 `${...}`）→ **如实返回空**，写进 `undetermined`：
  「真实内容未取到，生成时不得凭空写 categories/列表结构」

不许猜一个 cookie 塞进去 —— 猜错了请求全 403，排查成本更高。

#### 坑 3：把分类目录当成片单样例

第一版列表正则收 `type|vod|info`，结果 6 条样例全是「动作片/喜剧片/恐怖片…」分类链接。
侦察报告于是把导航当成了片单，下游 LLM 会照着生成一个「片单 = 分类」的源。

实测 lziapi 的真实详情页是 `/index.php/vod/detail/id/N.html`。
修正：匹配集合里显式排除 `/type/` `/list/` `/show/`。

## 三、rewrite 主流程（`engine.rewrite`）

```
① 侦察 → 有 blocker 就 aborted（不出源码）
② 组装证据（真跑结果 + 上轮失败 + 旧代码 + 站点片段 + 侦察报告）→ LLM
③ 静态闸门 _rewrite_static_check
④ write_with_verify（备份 → 写 → 回读）
⑤ 真跑复验 livecheck
⑥ 不过就带新死因重来，上限 3 轮 → verify_failed
```

### 核心判断：侦察不完整就**不生成**

```python
blockers = [u for u in rr['undetermined'] if '未取到' in u or '抓取失败' in u]
if blockers:
    return aborted('侦察不完整，拒绝生成（否则必然是编的）：' + '；'.join(blockers))
```

理由：没拿到真实列表/详情结构时生成的源，**一定是编的**，
跑起来是「假通过 + 零播放地址」，比原来的坏源更难排查。

### 静态闸门（写盘前）

| 检查 | 为什么 |
|---|---|
| 六接口缺一 | 壳直接不认这个源 |
| 语法错 | 加载即失败 |
| 含 `...省略` / `TODO:` / `<省略>` | 模型偷懒，一定是残稿 |
| `getName` 返回空串 | 用户列表里认不出是哪个站 |

> **`getName` 这条踩了假阳性**：第一版用全文搜 `return ""`，
> 结果正常源里 `_get()` 失败返回 `""`、`_fix()` 空值返回 `""` 全被判成「getName 空串」，
> 一个好源被拒。改成**按函数体 AST 查**才对。
> 教训：静态检查必须精确到作用域，全文正则会误伤。

### 两种产出形态不能混

| 档 | 产出 | 草稿字段 | 应用方式 |
|---|---|---|---|
| patch | `{"patch":{"edits":[{old,new}]}}` | `reply` | 逐字替换 |
| rewrite | `{"code":"<整份源码>"}` | `reply_code` | 整份覆盖 |

混在一起会让补丁被当成整份源码写进文件（文件只剩 3 行）。
`_system_prompt` 已按策略分叉，`apply_draft` 也按 `strategy` 走不同分支。

## 五、recon 离线自检（14 项，全绿）

不打网络 —— 沙箱出口时好时坏，联网测试会变成「今天绿明天红」，最后没人看。
联网部分靠 CLI 手动跑，自检只保证「给定 HTML → 结论」这段确定：

- 列表解析排除分类目录 / 取 title 属性 / 封面补全
- 三数字模板两个方向（单集多线路 → 第二个是 sid；多集 → 第三个是 nid）
- 分页三态（路径尾 / query / 判不出返回空）
- `meta refresh` / `location.replace` / 字面量 cookie / 模板串 cookie 不瞎猜
- 不可达 → `home_ok=None` 且 `undetermined` 有话说

## 六、边界如实说（M-R136）

- **没接真 LLM 跑过完整重写**：本轮用「宿主模型当修复器 + 假 chat 打桩」验证了
  编排、闸门、写盘、复验四段。真实模型产出的质量，沙箱测不了。
- **侦察只覆盖 GET + 静态 HTML**：纯 JS 渲染站（空壳 SPA）目前只能报
  「需找 XHR 接口」这条线索，不会自动去逆向接口。
- **不处理登录态/验证码**：带状态的站一律落 `undetermined`，不硬闯。
- **`episode_shape` 只认三数字模板**：其它形态（`/play/{id}-{n}.html` 等）不猜，
  原样把播放链接列表交给 LLM，由它判断。
